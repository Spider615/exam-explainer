# 「析题」全站 UI 重设计

> **一句话**：在不改变现有业务、接口与 Hash 路由的前提下，把 `web/` 重做成一套
> 面向老师的「学术编辑台」：暖纸色、深墨蓝、朱砂点睛；首页启动轻，试卷阅读稳，
> 动画是题目卡片的主舞台，答题卡诊断先给结论再给逐题证据。

## 背景

现有页面已经接通两条完整工作流：解析试卷与答题卡诊断。功能不缺，主要问题在体验：

- 页面像验证性后台，品牌、导航、主动作和内容之间缺少明确层级；
- 上传、日志、进度、列表连续堆叠，老师需要自己判断当前该看哪里；
- 试卷详情能展示题干、解答、原卷、动画和可信度信息，但视觉重量接近，核心内容不突出；
- 答题卡诊断正在从大卡片改成逐题表格，信息效率提高了，但整体视觉和小屏退化方式尚未统一；
- 动效主要用于进度信号，缺少稳定的页面过渡、展开反馈和防止布局跳动的约束；
- 现有 `styles.css` 由功能迭代逐段增长，设计变量、页面骨架和可复用状态组件边界不够清楚。

本设计经 2026-08-14 浏览器可视化评审确认。用户选择了「学术编辑台」方向、整站改造、
桌面优先，并决定页面品牌显示为「析题」，`exam-explainer` 继续作为技术名。

## 目标

- 整站统一重做登录、两种上传、任务库、试卷详情和答题卡详情。
- 让老师进入任一页面后，三秒内知道「这是什么、现在到哪、下一步做什么」。
- 让长题干、公式、动画与解题步骤形成稳定的阅读节奏，适合长时间使用。
- 让上传、轮询、完成、失败和恢复过程保持在稳定位置，减少等待焦虑和页面跳动。
- 保留所有可信度信息：原卷对照、公式低置信、动画门禁、读取重试、题号错位、得分对账与改判来源。
- 桌面端以 1440px 和 1024px 为主要验收宽度；390px 下保证功能完整、可读、可操作。
- 不引入新的 UI 框架或状态管理库，以现有 React、TypeScript 和 CSS 落地。

## 非目标

- 不修改后端 API、数据库、管线阶段或模型行为。
- 不改变 `#/paper`、`#/sheet`、详情路由与老地址兼容规则。
- 不改变动画场景契约、物理计算、门禁结论或现有 `SceneMount` 能力。
- 不新增班级、学生账号、分享协作、主题编辑器或运营数据。
- 不把技术日志删掉；只调整默认层级，正常状态下收起，故障时仍可查看。
- 不用 UI 掩盖失败，不把「没读清」写成「学生没作答」，不把「没有产物」画成空白。

## 设计方向

### 品牌与气质

页面品牌为 **「析题」**，技术名 `exam-explainer` 不再占据主视觉。

> 2026-08-15：这一节原来写的是「析题**。**」（朱砂色句点，当签名用）——
> 而第 19 行记的用户决定是不带句点的「析题」。实现时跟了这一节，上线后
> 用户问「这个怎么后面有一个句号」，确认去掉。前后不一致的锅在这份文档。
气质是克制的学术编辑台，不是企业 SaaS 后台，也不是深色开发工具。

| 维度 | 决策 |
|---|---|
| 底色 | 暖纸色，而不是纯白或冷灰 |
| 主色 | 深墨蓝，承担正文、导航和主要按钮 |
| 强调色 | 朱砂色，只用于主动作、当前位置和需要注意的变化 |
| 成功色 | 低饱和墨绿；警告用琥珀；失败用砖红 |
| 标题字体 | 宋体系，突出教辅与编辑感 |
| 正文字体 | 清晰的人文无衬线；数字和运行信息用等宽或衬线数字 |
| 表面 | 低对比细边框、轻阴影、10–16px 圆角；不使用玻璃拟态和大面积渐变 |

字体采用本地优先栈，避免外部网络依赖：标题以 `Songti SC` / `STSong` / 对应中文
衬线回退为主，正文以 `Avenir Next` / `PingFang SC` / `Microsoft YaHei` 回退。

保留现有的 `prefers-color-scheme: dark` 自动深色能力，但把它统一成同一品牌的「深墨夜色」
变体：深墨蓝底、暖白正文，朱砂与墨绿仍承担相同语义。本轮不新增手动主题开关，也不让
深色模式改变布局、信息层级或组件尺寸。

### 动效

- 普通悬浮、按钮、标签和背景变化：160–200ms；
- 折叠、任务卡状态切换和页面内容进入：200–240ms；
- 进度条继续使用宽度过渡，不做无法对应真实进度的循环填充；
- 首屏允许一次轻量分层进入，不给每个小组件单独加动画；
- 展开详情时预留或平滑扩展空间，避免内容突然把视口顶走；
- 尊重 `prefers-reduced-motion`，关闭装饰性进入和悬浮位移；
- 保留动画离开视口后不推进、全局暂停和键盘控制的现有逻辑。

## 全局信息架构

### 页面壳

登录后所有页面共用 `AppShell`：

```
析题          解析试卷   答题卡诊断                         周老师
──────────────────────────────────────────────────────────────
页面内容
```

- 品牌点击回到当前模式的任务库；
- 两个模式是一级导航，当前模式用底部朱砂短线表示；
- 账号与退出放右侧，不与页面标题争夺视觉焦点；
- 首页不使用永久侧栏，避免企业后台感；
- 进入试卷详情后才显示固定题目目录，正文获得稳定阅读宽度。

### 首页与任务库

模式首页由三层构成：

1. 一句说明当前工作流价值的页面标题；
2. 唯一的主动作——上传或准备分析材料；
3. 最近任务及少量可解释统计。

普通试卷是一块单文件上传卡。答题卡诊断保留三个独立材料槽：参考答案、原卷题目、
学生答题卡。三槽不能合并成一个「智能分类」入口，防止文件身份猜错导致错误答案入库。

任务库保留表格的扫描效率，但做三项调整：

- 名称、状态、题数和最重要结果排在一行；
- 删除等低频危险操作收进每行的更多菜单；
- 运行中、已完成、停止和需留意同时用文字与颜色表达，不只靠颜色。

## 试卷详情

### 页面骨架

桌面端采用两栏：190–220px 固定目录 + 自适应正文。目录包含返回入口、卷名、题目数量
和题号短标题；正文顶部只显示卷名、阶段概述和少量统计。

手机端不保留固定侧栏：目录改为题号抽屉或横向快速跳转，正文单列显示。

### 题目卡片顺序

每道题严格按以下顺序组织：

1. 题号、题型、分值、可信度与原卷对照；
2. 题干及选项；
3. 知识点和卷面参考答案（存在时）；
4. 动态讲解（存在动画时默认展开）；
5. 答案与解题步骤；
6. 假设、失败原因和低频技术信息。

原卷对照、公式低置信、文字层不可用、解题失败和动画重跑状态都保留现有语义。

### 动画是主舞台

有动画的题不把动画藏进折叠区或二级标签。题干之后直接出现「动态讲解」：

```
┌───────────────────────────┬──────────────┐
│                           │ 关键读数 LIVE │
│      物理动画画布          │ v  3.42 m/s  │
│                           │ T 18.6 N     │
├───────────────────────────┴──────────────┤
│ 当前画面说明                              │
├──────────────────────────────────────────┤
│ 暂停  重播  ━━━━━时间轴━━━━  1×  多情形    │
└──────────────────────────────────────────┘
```

- 复用现有播放/暂停、重播、时间轴、倍速、多情形和键盘控制；
- 画布与关键物理量同屏，不能让漂亮画面掩盖数值；
- 场景已有披露继续显示，明确哪些尺寸或时间被放大、归一化；
- 场景启动失败时显示静态首帧和明确错误，不留空白；
- 全卷顶部保留「全部暂停/播放」，老师投屏讲解时可一键控制；
- 动画之后紧跟答案和三步左右的推导，形成「看变化 → 看结论 → 看计算」的顺序。

## 答题卡诊断

### 上传与运行

- 参考答案明确标为必填；原卷题目为建议上传；学生答题卡为选填；
- 每个材料槽显示用途、已选文件、页数或大小和移除入口；
- 点击「开始分析」后，上传卡原地转换为运行状态，不跳到一张内容为空的详情页；
- 运行状态显示当前步骤、已处理页数、已识别题数和可理解的下一步；
- 原始日志默认折叠；任务完成且包含答题卡时，进入该学生的诊断结果页。

### 诊断结果页

结果页先回答「哪里丢分」，再允许逐题深挖：

1. 总分 / 满分、丢分、逐题合计是否与卷面总分一致；
2. 错题数、部分得分题数和优先提升知识点；
3. 需要留意的读取、题号绑定和得分对账问题，默认收成一行；
4. 可筛选的逐题结果。

逐题结果桌面端一题一行，固定字段为：题号、原图切片、学生答案、正确答案、判定与得分、
知识点、错误原因与提高建议、详情入口。手机端转换成一题一卡，不强迫整张宽表横向滚动。

原图切片必须紧挨判定，这是老师校对模型转写的直接证据，不能藏进二级页面。详情展开后
才显示判定依据、老师红笔答案、官方解答、改判和撤回改判。半对继续使用 `◐`，不混进
对或错；「没读清」「空着」「挂不上题」继续使用不同文字。

## 组件边界

在不重写业务逻辑的前提下，拆出少量清晰组件：

| 组件 | 职责 | 依赖 |
|---|---|---|
| `AppShell` | 品牌、模式导航、账号与页面宽度 | `App` 提供当前模式和导航回调 |
| `PageIntro` | 页面标题、说明与右侧辅助动作 | 纯展示 |
| `UploadCard` / `MaterialSlot` | 单文件上传与三类材料槽的共同视觉 | 现有上传回调与文件状态 |
| `JobProgress` | running / solving / finishing / done / error 的稳定位置 | 现有 `Job` 数据 |
| `StatusBadge` | 统一成功、运行、停止、警告和失败语义 | 纯展示，文本必填 |
| `LibraryTable` | 两种任务库共享表面与响应式行为 | 各模式继续提供自己的列数据 |
| `PaperSidebar` | 题号目录与快速跳转 | 现有题目列表 |
| `MetricCard` | 试卷与答题卡的摘要数字 | 纯展示 |
| `SceneMount` | 保留场景生命周期与控制；只重做外观和布局 | 现有场景契约 |
| `SheetResultRow` | 逐题结果与展开详情 | 现有 `SheetRow` 和改判 API |

不为了视觉统一强行合并 `PaperView` 与 `SheetView`，也不把两种上传流程塞进同一个巨大组件。

## 数据流与路由

- `App` 继续读取 Hash，解析 `paper` / `sheet` / open / sheet id；
- `GET /api/papers?mode=...`、详情接口和进度接口不变；
- 列表继续定时刷新，打开详情后由详情页负责自己的轮询，避免重复请求；
- 上传组件继续持有任务句柄，刷新列表但不提前卸载自己；
- 动画脚本继续由 `PaperView` 加载，`SceneMount` 在场景注册后挂载；
- 改判继续调用现有 `regrade`，成功后重新拉取答题卡；
- `#/p/<卷名>` 老地址继续按现有规则跳到正确模式。

## 状态与错误处理

所有页面必须显式覆盖 loading、empty、running、partial、done、error 与 unauthorized。

- 初次加载使用骨架或稳定占位，不用一个孤立的「载入中…」造成布局跳动；
- 会话过期继续回登录页，不把列表清空伪装成「没有数据」；
- 网络重试、任务句柄丢失、上传撞名和管线失败继续保留当前准确话术；
- 正常运行时只展示人能理解的步骤，技术日志折叠；失败时日志入口提升；
- 删除必须确认；危险动作不在静止状态下满屏红色；
- 动画失败退回静态首帧；公式和文字转写失败保留原卷入口；
- 答题卡读取告警合并成摘要，但不删除任何真实诊断；
- 状态颜色必须同时配合文字、图形或符号，满足色觉差异用户。

## 响应式与可访问性

- 1440px：完整双栏试卷详情和宽诊断表；
- 1024px：压缩边距与目录宽度，动画仍保持画布 + 读数双栏；
- 390px：顶部导航可换行或水平滚动；详情单列；答题卡表格转逐题卡；
- 所有按钮、文件槽、展开项和场景控制有可见的 `:focus-visible`；
- 图片有明确 `alt`，输入有真实 `label`，进度和错误使用 `aria-live`；
- 正文与背景达到 WCAG AA 对比度；辅助灰字不能淡到不可读；
- 移动端主要点击区域至少约 44px；
- 动效遵循 `prefers-reduced-motion`，不能移除唯一的运行状态信号。

## 验收与测试

### 自动验证

- `cd web && npm run build`：TypeScript 与 Vite 构建通过；
- 运行与前端投影、上传、答题卡数据相关的 Python 测试；
- 若实现中新增可独立测试的纯函数（状态映射、响应式数据投影），为其补充测试；
- 最后运行项目全量测试，确认 UI 重构没有破坏 API 或管线约束。

### 浏览器验收

至少检查 1440px、1024px 和 390px 三种宽度，并覆盖：

1. 登录、验证码、错误和重新发送；
2. 普通试卷上传、运行、完成、失败和句柄恢复；
3. 答题卡三类材料选择、排序、运行与完成跳转；
4. 两种任务库的空、运行、完成、警告和删除；
5. 试卷目录、原卷对照、动画播放/暂停/时间轴/倍速/多情形、动画失败静态首帧；
6. 答题卡摘要、筛选、原图、逐题详情、半对得分、改判和撤回；
7. 键盘焦点、减少动态效果和窄屏操作。

### 完成标准

- 页面品牌、颜色、字体、间距、圆角与状态语义一致；
- 五条核心路径均能完成，原有业务信息无丢失；
- 主要页面没有横向溢出、内容遮挡和展开后的不可达操作；
- 动画在有场景的题里默认可见，控件与读数可用；
- 答题卡首屏能直接回答总分、丢分、错题与优先知识点；
- 构建、相关测试和全量测试均通过，并有浏览器实测证据。
