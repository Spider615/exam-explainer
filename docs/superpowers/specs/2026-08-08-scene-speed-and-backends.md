# ⑤ 提速与后端切换：实测记录

> 2026-08-08。这份文件是**实测数据的存档**，不是设计。所有数字都是跑出来的，
> 每条都注明了样本量。设计与验收在 `2026-08-08-scene-codegen-design.md`。

## 一、时间到底花在哪（这是整轮的起点）

⑤ 一道题（q13）跑一次，用 `claude -p --output-format json` 拿到明细：

| 项 | 数值 |
|---|---|
| 总耗时 | 1322 秒 |
| 纯 API 等待 | 1296 秒（**98%**） |
| 门禁 `verify.py` | 2.1 秒 |
| 拼装 `build.py` | 0.08 秒 |
| **合计确定性部分** | **2.2 秒（0.2%）** |

**⑤ 不是一次长生成，是一个 54 轮的 agent 会话。** 53 次 tool 调用的构成：

| 类别 | 次数 | 明细 |
|---|---|---|
| 探索/导航 | **20** | grep×6、cd×5、ls×4、读别的场景的文件×3、读 `scenegen.py`×1 |
| 验证 | **15** | `verify.py`×12、`build.py`×**3** |
| 真正在写 | **7** | Write×2、Edit×5 |
| 读契约与 spec | 2 | |
| 算参数 | 3 | python3 |

而输出 token 的构成更关键：

| | |
|---|---|
| 会话里可见的产出 | 10,783 字符 ≈ 3,594 token |
| API 报的 output token | **59,971** |
| 差额（thinking，4 个块） | **约 56,000 token（93%）** |

**结论：瓶颈是「轮数 × 每轮思考量」，不是「要写多少字节」。**

这解释了为什么此前两次优化输出量都没换来提速：
砍 47% 的代码量 → 时间没变；换 41% 更小的声明式 → 反而更长。

## 二、两处修好之后（订阅 sonnet）

**修法**：
1. `harness/check.py` —— 把 `build && verify` 合成一条命令。
   原因：agent 只跑后半句，12 次 verify 里至少 9 次验的是没重拼的旧产物。
2. 重写 `BRIEF_CODEGEN` —— 自带完整示例、样式类清单、字宽表，并明写「别翻仓库」。
   原因：它跑去读 `q13-gen6.js` 和 `scenegen.py` 找例子，因为提示词里没给。

**q13 实测（n=1）**：

| | 改前 | 改后 | |
|---|---|---|---|
| tool 轮数 | 54 | **7** | −87% |
| 耗时 | 1322 秒 | **652 秒** | −51% |
| 输出 token | 110,513 | 59,971 | −46% |
| 缓存读入 | 641 万 | 53 万 | −92% |
| 折合费用 | $4.66 | $1.56 | −66% |
| 门禁 | PASS | PASS | |

**再加 `--effort low`**：188 秒、16,327 token、$0.73，**门禁仍然 PASS**。
`claude --effort` 取值：`low / medium / high / xhigh / max`。

## 三、后端切换：方舟

### 模型能力实测

`deepseek-v4-flash-ga-260731`（火山方舟 cn-beijing）：

| 能力 | 结果 |
|---|---|
| 基本对话 | ✅ |
| **函数调用** | ✅ `finish_reason=tool_calls` —— 能驱动 claude CLI |
| **读图** | ❌ `Model do not support image input` |

`doubao-seed-evolving`：读图 ✅（18 秒读出带 LaTeX 的选项），
`.env` 里 `ARK_VISION_MODEL` 本来就是它。

**所以 ②b 公式识别只能用豆包，不能用 DeepSeek。**

### 慢的根因不是垫片

| 排除项 | 证据 |
|---|---|
| 垫片延迟 | 方舟侧 146 秒 / 总 154 秒 —— **垫片只占 5%** |
| prefill | 输入涨 11.9 倍，耗时只涨 1.7 倍 |
| 没有 prompt 缓存 | 重发同样长输入，缓存命中 7680 token、1.5 秒 |

**真因**：DeepSeek-V4-Flash 是推理模型，同一道物理题输出 1774 token 里
**1769 个是 reasoning**。生成速率一直是 ~80 tok/s —— 不是模型慢，是它生成了 6 倍的量。

### 思考预算开关（实测哪些参数有效）

同一道物理题：

| 参数 | 耗时 | 输出 token | reasoning |
|---|---|---|---|
| 不带参数（基线） | 22.4s | 1774 | 1769 |
| **`thinking:{"type":"disabled"}`** | **3.6s** | **286** | **0** |
| `thinking:{"type":"auto"}` | 15.8s | 1241 | 1236 |
| `thinking:{"type":"enabled","budget_tokens":256}` | 16.5s | 1324 | 1319（**budget 被忽略**） |
| `reasoning_effort:"low"` | 34.2s | 2564 | 2559（**更慢**） |
| `reasoning_effort:"minimal"` | 1.4s | 19 | 0（答案不完整） |

**只有 `thinking:{"type":"disabled"}` 管用。** 关掉之后答案照样对
（推导写进可见输出，实测斜面题两者都给出 3.58 m/s）。

已在 `pipeline/arkshim.py` 加开关：环境变量 `EXAM_ARK_THINKING=disabled`。
默认不传这个字段，保持模型默认 —— 不设就跟以前一模一样。

### ②b 为什么不能借 arkshim 走 claude CLI

最省事的想法是 `claude -p --model doubao-seed-evolving` 加垫片，一行环境变量切完。
**不行**：`arkshim.blocks_to_openai` 处理 `tool_result` 时只把 `text` 块串起来，
图片块没有 `text` 键，会被静默丢成空串。而 CLI 读图靠的正是 Read 的 tool_result。

图在垫片里消失 → 模型收到「请读这张图」加空内容 → 一本正经地编出选项。
**不报错、结果看着还像对的**，是最坏的那一类。所以 ②b 走直连。

### ④ 换脑子的实测（n=2 能比，第 3 题被判「不适合做动画」）

| 题 | 原来 claude-sonnet-5 | 现在 DeepSeek-V4-Flash | ④b 自检 | 耗时 |
|---|---|---|---|---|
| 北京卷 q5 | 7 条断言（lint 2 处） | **判「不适合做动画」** | — | 25s |
| 北京卷 q17 | 15 条断言（lint 0 处） | **6 条**（lint 1 处） | 6/6 过 | 105s |
| 重庆卷 q13 | 22 条断言（lint 1 处） | **14 条**（lint 0 处） | 14/14 过 | 132s |

**能用**：写出来的 spec 自洽，20 条断言全部通过 ④b（拿 spec 自己的参考实现验
spec 自己的断言）。速度和订阅那条路差不多，④ 本来也不是瓶颈。

**代价，两条**：

1. **断言少了四到六成**（15→6、22→14）。断言就是 ⑥ 的 L4 那一层 ——
   **spec 弱，门禁就弱**，而 ④b 只检自洽、检不出「不够严」。
   q17 的 lint 直接点破了：「没有任何单调性/守恒量断言，过程中间怎么走完全不受
   约束，只要两端对上就能过」。
2. **它会把 sonnet 认为能做的题判成不能做**（q5）。理由写得通顺（波形辨析题
   没有随时间演化的量），但这是**静默减产** —— 少一道动画不会有人来报错。

这两条都不在 n=1 的范围内解决得了，记在这儿，别忘了。

## 六、落地时踩到的两个坑（都已修）

### 1. `.env` 改了不生效 —— 后端进程用的是启动时的快照

`store.py` 读 .env 用 `os.environ.setdefault`，后端一启动那份 .env 就被烤进它的
`os.environ`；而 `api.run_step` 把 `dict(os.environ)` 整个传给子进程，子进程自己
那句 `setdefault` 于是是空操作。

结果：配置落进 .env、测试全绿、**页面上跑的仍然是订阅**，日志里一个字都没有。
已修（`step_env()` 让 .env 有最终解释权，`dotenv_drift()` 把变更写进任务日志）。

### 2. 垫片复用不核对身份

思考开关和 key 都是垫片**进程启动时读一次**的常量。原来 `ensure()` 探到端口通
就复用 —— 上一轮开思考的垫片没退出，这一轮改成关思考也白改。
落 .env 那天真撞上了：8898 上正蹲着上一轮实测留下的旧垫片。
已修（`GET /` 出身份牌，对不上当场停）。

### 附：一个不是 bug 的 bug

⑤ 冒烟第一次跑报 `KeyError: 'check'`，指向 `BRIEF_CODEGEN.format()`。
源码里 `check=` 逐字验过是在的，同样输入单独跑 `format()` 也成功。
`rm -rf pipeline/__pycache__` 之后就正常了 —— **陈旧字节码**。
traceback 显示的是新源码、跑的是旧字节码，所以看起来自相矛盾。
下次再遇到「代码明明是对的」，先清 `__pycache__`。

## 七、保留意见（每一条都要记住）

1. **样本量都很小。** ⑤ 的每个配置每道题只跑了一次；④ 换脑子的对照是 n=2。
2. **④ 关思考仍然没验过。** 让它保持开思考是推断加「断言已经偏少了，不能再省」，
   不是实测。
3. **④ 的断言变少这件事没有门禁挡着。** `spec.lint` 会提醒，但只是记进
   `why_not` 字段，不拦。要不要拦是个待定的产品决定。
4. `--effort low` 在订阅上只验过 q13 一道。
5. **三把方舟 key 完全相同**（`ARK_API_KEY` / `EXAM_SPEC_KEY` /
   `EXAM_SCENE_ARK_KEY`），是同一个账号。.env 里原来那两句「属于不同账号」
   的注释是错的，已删。
