# 答题卡诊断：判对错、挂知识点、给提升建议

## 背景

现有产品把一份试卷 PDF 变成「逐题讲解 + 物理动画」，服务对象是老师。但它只到「这份卷子怎么解」为止，回答不了老师真正要问的下一个问题：**我这个学生哪里不行、该补什么**。

老师手上有两样东西：一份带答案的试卷，一份学生做完的答题卡。这两样凑在一起，本来足以推出「这个学生哪些知识点薄弱」，而现有管线已经产出了讲解和动画 —— 诊断出薄弱点之后，「怎么提升」直接就有了实质内容，不必再编一段空话。

## 目标

- 老师上传一份带答案的试卷和一份学生手写答题卡，得到一份诊断报告。
- 报告逐题给出**对 / 错 / 空白 / 判不了**，每一题都能当场对照答题卡上的原图。
- 报告给出**薄弱知识点**，知识点来自受控词表，能跨题聚合。
- 报告给出**怎么提升**，且每条建议都落到具体题号上，接现有的逐题讲解与动画。
- 自动阅卷判错时，老师能一键改判，改判后诊断可重算。

## 非目标

- **不判分数**。只判每道题对错，不给分、不给过程分、不算总分。
- **不读手写推导过程**。只认每题的最终作答。「错在哪一步」不在本期范围。
- **不做班级**。一次一份答题卡、一个学生。不建 `students` 表，不做班级汇总。
- **不做学生账号**。报告只给老师看，不导出、不分享。
- **不做拍照纠偏与去阴影**。第一版靠提示老师拍正，实测证明需要再补。
- **不改 `segment.py`**。它是现有链路的核心，新功能不动它。

## 关键决策

| 决策 | 取舍 |
|---|---|
| 答题卡是手写扫描件/照片 | 最真实也最难，手写识别是本功能的主要风险 |
| 答题卡未批改，系统自动阅卷 | 老师不用先批一遍，代价是「哪题错」从事实变成推断，必须配红绿灯 |
| 知识点用内置受控词表 | 名字统一才能聚合、才能说「这个点错了 2 次」；代价是要维护词表 |
| 逐题原图对照 + 老师可改判 | 这是本功能唯一的红绿灯，跟 `mathvlm.py`「原图始终保留」同源 |
| 整页一次读，判错的再裁块复读 | 便宜的筛子排在贵的前面，跟 ④c 排在 ④ 前面同源 |
| 不引 sympy 做符号等价 | 它解析带单位带下标的 LaTeX 会**静默**判错，正是本项目最怕的错 |

## 架构：两条链，一个交汇点

```
试卷侧（一份卷子跑一次，之后所有学生复用）
    ① 摄入 → ② 切分 ─┬─ ②b 公式 → ③ 解题 → ③b 目录 → ③c 知识点标注 ← 新增
                     │
                     └─ ②c 标准答案抽取                            ← 新增
    ④c → ④ → ④b → ⑤ → ⑥ → ⑦   照跑不动

                    题目 · 标准答案 · 知识点标签 · 讲解 · 动画
                                    │
答题卡侧（每个学生一次）              ▼
    Ⓐ 摄入   → 页面图
    Ⓑ 读答案 → 整页一次拿到 [题号, 框, 最终作答]
    Ⓒ 判对错 → 代码为主；判错的裁块复读一次
    Ⓓ 出报告 → 错题 → 知识点 → 薄弱点排序 → 接讲解与动画
```

两条链解耦的理由：知识点标签、标准答案、讲解、动画都是**这份卷子的属性**，与哪个学生做的无关。答题卡那条链只读试卷侧的数据，不写。

新增的两个试卷侧步骤位置按成本排（延续 ④c 排在 ④ 前面那条）：

- **②c 标准答案抽取**：从 ①摄入 的 `doc.json` 里找「参考答案」段落，按 ② 切出来的题号列表对应过去。只依赖 ①②，与 ②b／③ 并行，不动 `segment.py`。
- **③c 知识点标注**：整卷一次调用。放在 ③ 之后是因为用得上解法 —— 知道这道题怎么解的，比只看题干更判得准它考什么。

**白捡的红绿灯**：②c 抽出的老师答案与 ③ 的 AI 答案比对一次，不一致就在页面标出来。要么 AI 解错了，要么那份答案有误。两份数据都已在库里，这条不额外花钱，却同时给 ③ 加了一层校验，并防止拿一份错答案去判学生对错。

## 数据模型

写法沿用 `schema.sql` 现有分界线：产品数据进列，管线中间量进 jsonb。

```sql
-- 一份答题卡 = 一个学生的一次作答。
-- **不建 students 表**：范围定死单人、不做班级，学生就是老师随手填的一个标识。
-- 建了表就要配增删改查和「同一学生的历次考试」，那是另一个功能。
CREATE TABLE answer_sheets (
  id            bigserial PRIMARY KEY,
  paper_id      bigint NOT NULL REFERENCES papers(id) ON DELETE CASCADE,
  owner_id      bigint REFERENCES users(id) ON DELETE SET NULL,
  student_label text,
  source_pdf    text,
  n_pages       int NOT NULL DEFAULT 0,
  created_at    timestamptz NOT NULL DEFAULT now(),
  -- 老师改判会 touch 它。诊断过没过期，拿它跟 diagnoses.created_at 比 ——
  -- 跟 papers.assembled_at 判 out.html 旧没旧是同一个套路
  updated_at    timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE sheet_answers (
  id          bigserial PRIMARY KEY,
  sheet_id    bigint NOT NULL REFERENCES answer_sheets(id) ON DELETE CASCADE,
  -- **可空**：认出了题号但卷子里没这道题（串号、学生多写一道）。
  -- 挂不上就是挂不上，页面明说，不许猜一个最近的题号安上去
  question_id bigint REFERENCES questions(id) ON DELETE CASCADE,
  n           int  NOT NULL,
  raw_text    text,        -- 模型认出的最终作答，**原样**，不加工
  norm        text,        -- 归一化后的形式，判定拿它比
  crop_rel    text,        -- 原图切片的 assets.rel_path
  box         jsonb,
  page        int,
  read_conf   text,        -- 模型自称的把握 high/medium/low
  reread      boolean NOT NULL DEFAULT false,

  -- **verdict_by 才是红绿灯** —— 同一个「错」，代码判的和模型判的
  -- 可信度差一个量级，页面必须分得出来
  verdict         text,    -- right | wrong | blank | unsure
  verdict_by      text,    -- code | model | teacher
  verdict_why     text,

  -- 老师改判**单独一列，不覆盖系统原判**。留着原判才看得出系统错在哪，
  -- 也才撤得回来。读取一律走 store 里那一个 COALESCE 函数，不让每个
  -- 调用点各写一份 —— api.ts 那次 401 广播就是这个教训
  teacher_verdict text,

  UNIQUE (sheet_id, n)
);

-- 知识点受控词表。code 是稳定代号而不是自增 id：词表是版本管理的种子
-- 数据，重灌一次自增 id 就全漂了，code 不会。
CREATE TABLE kp_catalog (
  code    text PRIMARY KEY,
  chapter text NOT NULL,
  name    text NOT NULL,
  aliases jsonb NOT NULL DEFAULT '[]'
);

CREATE TABLE diagnoses (
  sheet_id   bigint PRIMARY KEY REFERENCES answer_sheets(id) ON DELETE CASCADE,
  weak_kps   jsonb NOT NULL DEFAULT '[]',
  advice     jsonb NOT NULL DEFAULT '[]',
  model      text,
  created_at timestamptz NOT NULL DEFAULT now()
);

ALTER TABLE questions ADD COLUMN IF NOT EXISTS kps            jsonb NOT NULL DEFAULT '[]';
ALTER TABLE questions ADD COLUMN IF NOT EXISTS ref_answer     text;
ALTER TABLE questions ADD COLUMN IF NOT EXISTS ref_answer_src text;   -- paper | none
```

**没有 `state` 列**，有意为之。现有 `papers` 也没有 —— 进度由 `stage_of` 从库里的计数反推。答题卡链同理：有没有页面图 → 有没有 `sheet_answers` → 有没有 `verdict` → 有没有 `diagnoses`。多一个状态列就多一个会跟事实不同步的东西。

**`kps` 用 jsonb 存 `[{code, why}]` 而不是关联表**：范围是单人单卷十几道题，聚合在应用层做就够，不需要 `GROUP BY`。代价是 code 没有外键保护，所以 ③c 写入时要拿 `kp_catalog` 校一遍，挂不上的明说挂不上。将来真要跨卷追踪同一学生，再补关联表。

**原图切片走现有 `assets` 表，一个字都不改**：`paper_id` 填答题卡所属的卷子，`rel_path` 用 `sheets/<sheet_id>/q7.png` 带前缀 —— `UNIQUE (paper_id, rel_path)` 仍成立，存储层抽象（local/minio 切换不影响前端 URL）和 `api.py` 的资产代理全都白拿，删卷子时切片跟着 CASCADE 掉。

## 试卷侧新增

### ②c 标准答案抽取

输入 `work/<卷名>/doc.json` 和库里已切好的题号列表，输出每题的 `ref_answer`。

纯代码优先：找「参考答案」「答案」这类段落起点，按题号切开。切不出来（版式特殊、答案分散在每题后面）才叫一次模型兜底。抽不出来的题 `ref_answer_src='none'`，不留空猜 —— 这些题在 Ⓒ 一律判 `unsure`，并写明原因是卷子里没有答案，不是学生的问题。

### ③c 知识点标注

整卷一次调用。输入每题的题干 + ③ 的解法 + 词表全文，输出 `[{n, kps:[{code, why}]}]`。

三条约束：

- **只能从词表挑 code**，编出来的一律丢掉
- 一道题最多挂 3 个。挂满等于没挂
- `why` 是针对**这道题**的一句话（「用动量守恒求碰后速度」），不是知识点定义

挂不上就 `kps` 留空，页面明说「这道题没挂上知识点」。不硬塞一个最接近的 —— 塞进去的标签会污染薄弱点统计，而且没人看得出来它是塞的。

词表种子放 `pipeline/kp_seed.json`，跟代码一起版本管理，两级（章 → 知识点），约两三百条覆盖高中物理：

```json
{"code": "mech.newton2",  "chapter": "力学",   "name": "牛顿第二定律",
 "aliases": ["牛二", "动力学基本方程", "F=ma"]}
```

`aliases` 是给 ③c 挂标签时容错用的。

## 答题卡侧

### Ⓐ 摄入

新脚本 `pipeline/sheet.py`。`ingest.py` 靠 pypdf 读文字层，答题卡没有文字层，一个字都取不到，不能复用。

- 扫描 PDF → 逐页渲染 PNG（渲染那段代码 `ingest.py` 里现成，复用）
- 手机照片 → 直接用，但**按 EXIF 转正**（横过来的照片模型认不出题号）
- 存进 `assets`，`rel_path = sheets/<sheet_id>/page/pNN.png`

**分辨率分两档**，与后面两遍读对应：整页读用 150dpi（认出短答案和位置足够），裁块复读用 300dpi（这时才需要看清笔画）。`mathvlm.py` 就是 300 渲染、150 存图这个配比。

### Ⓑ 读答案

整页图进，`[{n, box, answer, conf}]` 出。

提示词上三条从 `solve.py` 的经验来 —— 它记着「DeepSeek 老老实实回 `NEED_FIGURE` 而不是编一个读起来合理的答案」，**给模型一个明确的认输出口，比反复叮嘱别猜有用得多**：

1. 认不出就回 `unreadable`，明写「认不出比猜错好」
2. **题号必须是图上真实认出来的**，不许按顺序编。没看到题号回 `n: null` 加位置描述 —— 这是防串题的主要手段
3. 空白回 `blank`，不许拿附近的字凑

拿到 `box` 之后**当场按框裁出小图存进 `assets`**（`sheets/<sheet_id>/q7.png`），写进 `sheet_answers.crop_rel`。这一步不能推迟到「老师要看时再裁」：页面图有可能已经被清理，而原图切片是本功能唯一的红绿灯，它必须和判定一起落库。

跨页大题（写不下续到下一页）：同一题号在多页出现按页序拼接，`box` 存第一处。

### Ⓒ 判对错

`verdict` 只有四个值，判定条件不许有第五种解释：

| verdict | 什么时候 | 计入薄弱统计吗 |
|---|---|---|
| `right` | 归一化后与标准答案相等，或模型判等价 | 进分母 |
| `wrong` | 归一化后不等，或模型判不等价 | 进分子和分母 |
| `blank` | Ⓑ 回了 `blank`，该题没有作答 | **都不进** |
| `unsure` | Ⓑ 回了 `unreadable`（认不出），或该题没有标准答案（`ref_answer_src='none'`） | **都不进**，但要在报告里单独列出来 |

`blank` 和 `unsure` 都不进统计，但含义不同，页面上要分开显示：前者是学生没写，后者是**系统没能力判**。把后者混进「错」等于拿系统的无能去当学生的薄弱点。

**确定档（`verdict_by='code'`）**

- 选择题：归一化成大写字母集合，与标准答案比集合相等
- 数值：`1.5` / `3/2` / `1.5m/s` / `1.5 m/s` 提取数值和单位后按相对误差比
- 表达式：LaTeX 归一化（去空格、`\dfrac`→`\frac`、`·`→`\cdot`）后字符串比

**不引 sympy 做符号等价。** 它解析带单位带下标的中文物理题 LaTeX 容易翻车，而翻车的样子是「静默给出一个错误的等价判断」—— 学生答对的题被判错，凭空造出一个薄弱知识点，页面上一切看起来正常。代码档只做**不会静默出错**的两件事：归一化字符串比、数值比，它们要么明确相等要么明确不等，没有第三种。

**推断档（`verdict_by='model'`）**：形式差得远、代码判不了的，给标准答案与学生作答，**只问「这两个是不是同一个答案」，不问对错**。页面上与代码判的区分开。

**判错的题一律裁块复读一次。**

理由是代价不对称：判对了没人受损；**判错了会凭空造出一个假的薄弱知识点**，而薄弱知识点是本功能唯一的产出。错题通常是少数（十几道错三五道），复读很便宜。复读用 300dpi 单题单次调用，问题更聚焦。两次结果不一致以复读为准，但**两次都留着**，页面标「复读后改判」。

复读的四个触发条件：`verdict='wrong'`、`verdict='unsure'` 且原因是认不出、`read_conf='low'`、题号挂不上卷子。复读只跑一次，复读后仍认不出就维持 `unsure` —— 不无限重试，读不出来是事实，说出来比反复烧钱强。

**`blank` 不是 `wrong`。** 卷子最后几道大题空白多半是时间不够而不是不会。混成「错」会把最后几个知识点全标成薄弱 —— 全是假的。空白不计入薄弱统计，报告里单独说一句「有 3 道题空白，未计入诊断」。

### Ⓓ 诊断

**薄弱点按比例排，不按错题数**：`错的道数 / 该知识点在这份卷子上的总道数`。错 2/2 比错 2/5 严重得多。

- 代码判错的和模型判错的分开计数，报告写「其中 1 道是推断判定」
- `blank` 和 `unsure` 都不进分子也不进分母（见 Ⓒ 的判定表）
- 某知识点在这份卷子只出现一道且错了 → 标「只考了一道，样本不足」。一道题撑不起「你这个点弱」这个结论，但值得提一句

**「怎么提升」定死结构**，每个薄弱知识点下挂三样**已经存在于库里**的东西：

1. 这次错的那几道题 —— 题干 + 学生作答原图切片 + 标准答案
2. 现成的逐题讲解 —— `solutions.steps`、`key_facts`、`assumptions`
3. 现成的动画 —— `scenes` 里过了门禁的那些

模型只负责最后一小段：把这几道题串起来说一句「你这几道都栽在同一处……」。**这段话里必须出现具体题号，没有题号的建议直接丢掉重生成。** 「多练习动量守恒相关题目」这种话写出来和没写一样。

## 页面

入口在试卷页 —— 答题卡挂在某份卷子上，不是独立的东西。`PaperView` 下面多一块「学生答题卡」列表，点开是诊断报告。

```
张三 · 2025年高考北京卷物理真题          [重新诊断]

逐题  1 ✓  2 ✓  3 ✗  4 ✓  5 —  6 ✗  7 ✓ …     ← ✗ 默认展开，✓ 折叠
      ┌──────────┐  认出的作答：B
      │ 原图切片  │  标准答案：  C
      │（学生手写）│  判定：错 · 代码判定 · 复读后改判
      └──────────┘  [改判为对]

薄弱知识点
  1. 动量守恒定律  错 2/2 · 力学
     这次错的：第3题、第6题
     「两道都栽在同一处：碰后动量写成了标量相加…」
     ▸ 第3题 讲解 + 动画    ▸ 第6题 讲解

  2. 法拉第电磁感应定律  错 1/3 · ⚠ 其中 1 道是推断判定

有 3 道题空白，未计入诊断（第14、15、16题）
判定与建议由 AI 生成，未经人工审核 —— 逐题原图就在上面，请对照
```

三条硬约束：

- **原图切片必须挨着判定，不能藏进二级页面**。老师一眼能校对是本功能唯一的红绿灯，藏一层等于没有
- **`verdict_by` 要显示**（代码判定 / 推断判定 / 老师改判）
- **改判后诊断标为过期，不自动重跑**。连改五题跑五次模型不合理；但也不能默默显示旧报告 —— 明确标「判定改过了，这份诊断是旧的」，配「重新诊断」按钮。与 `assembled_at` 判 `out.html` 旧没旧同一模式

进度与失败直接复用现有机制：答题卡链四步照 `stage_of` 从库里反推，页面一排标志，`failedStage` 把红色画在挂掉那一格。**同卷同学生不许同时跑两条链**复用 `CLAIMS` + 409 那道闸。

## 失败处理

分界线：**缺一条数据就说缺这一条，不要让整份报告消失**；反过来，读不出任何东西就得老实失败，不能拿一份九道题的残报告冒充完整诊断。

| 情况 | 处理 |
|---|---|
| 传的不是 PDF/图片 | 400，当场拒 |
| 整页读回来一道题都没有 | **失败**。多半拍歪了或传错文件，提示重拍 |
| 卷子 16 题只认出 9 题 | **不失败**，警告「有 7 道题没在答题卡上找到」并列出题号 |
| 认出的题号卷子里没有 | **不失败**，`question_id` 留空，单独列出来 |
| ②c 没抽出标准答案 | 该题标 `unsure`，写明「这份卷子没有标准答案」，不算错也不算对 |
| 一道题都没错 | 不编薄弱点，直接说「这次全对」 |
| 建议里没有题号 | 重生成一次；仍没有就只展示错题和讲解，**不展示建议** |

## 测试

- **判对错的归一化是纯函数，要测厚** —— 选择题字母集合、数值+单位提取、LaTeX 归一化。这是本功能里唯一能真正自动测的部分
- ②c 答案抽取、③c 知识点挂标签：拿库里现有九份卷子当样本跑，人工核对
- 端到端：需要真实的手写答题卡样本

## 实施顺序

**本功能最大的风险是「VLM 到底认不认得准手写作答」，而它在拿到真实样本之前完全验证不了。**

所以第一步不是建表、写 API、写页面，而是：**拿一份真实的手写答题卡（或自己手写一份拍照），只跑 Ⓑ 那一步，看整页读出来的题号和答案对不对。**

识别率能用，后面按部就班；不能用，整个方案要重新想（可能退回「老师批改后再传」，那是完全不同的一条链）。先花半天探掉这个风险，比四张表建好之后才发现地基不稳便宜得多。

风险探掉之后分三期，**每一期都要落到页面上**（只做到库和 API 不算完成）：

| 期 | 做什么 | 页面上能看到什么 |
|---|---|---|
| 一 | 词表 + ②c + ③c，`questions` 补三列 | 试卷页每题显示知识点标签和卷子上的标准答案；AI 答案与卷子答案不一致的题打标记 |
| 二 | `answer_sheets` / `sheet_answers`、Ⓐ Ⓑ Ⓒ、上传与改判 API | 上传答题卡 → 逐题对错 + 原图对照 + 改判。**没有诊断也已经能用** |
| 三 | `diagnoses`、Ⓓ、薄弱点与建议 | 完整报告，接讲解与动画 |

第一期不碰答题卡，用库里现有九份卷子就能验证，而且它自己就有价值 —— 老师能看到这份卷子考了哪些知识点，还能发现 AI 解错的题。第二期交付的是「自动阅卷」，不依赖诊断也成立。这样任何一期停下来，前面的都不白做。
