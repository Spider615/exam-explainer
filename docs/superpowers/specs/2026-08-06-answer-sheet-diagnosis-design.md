# 答题卡诊断：判对错、挂知识点、给提升建议

> **2026-08-07 修订。** 输入形态变了：答题卡是**多张图片**，试卷**可能是多张图片、也可能是一份 PDF**。
> 这带来一条全新的摄入路（图片没有文字层也没有坐标，①② 用不了），以及一个「一次传完」的单入口。
> 受影响的章节：架构、摄入层、上传入口、②c、实施顺序。判对错与诊断那两节基本没动。

## 背景

现有产品把一份试卷 PDF 变成「逐题讲解 + 物理动画」，服务对象是老师。但它只到「这份卷子怎么解」为止，回答不了老师真正要问的下一个问题：**我这个学生哪里不行、该补什么**。

老师手上有两样东西：一份带答案的试卷，一份学生做完的答题卡。这两样凑在一起，本来足以推出「这个学生哪些知识点薄弱」，而现有管线已经产出了讲解和动画 —— 诊断出薄弱点之后，「怎么提升」直接就有了实质内容，不必再编一段空话。

## 目标

- 老师**一次投三样**：题目（图片或 PDF）、答案（可选）、学生答题卡图片，得到一份诊断报告。
- 报告逐题给出**对 / 错 / 空白 / 判不了**，每一题都能当场对照答题卡上的原图。
- 报告给出**薄弱知识点**，知识点来自受控词表，能跨题聚合。
- 报告给出**怎么提升**，且每条建议都落到具体题号上，接现有的逐题讲解与动画（图片试卷只有讲解）。
- 自动阅卷判错时，老师能一键改判，改判后诊断可重算。

## 非目标

- **不判分数**。只判每道题对错，不给分、不给过程分、不算总分。
- **不读手写推导过程**。只认每题的最终作答。「错在哪一步」不在本期范围。
- **图片试卷不做动画**。跑到 ③ 讲解为止，④⑤⑥ 不进。
- **不做班级**。一次一份答题卡、一个学生。不建 `students` 表，不做班级汇总。
- **不做学生账号**。报告只给老师看，不导出、不分享。
- **不做拍照纠偏与去阴影**。第一版靠提示老师拍正，实测证明需要再补。
- **不改 `segment.py` / `anchors.py`**。它们是现有链路的核心，也是本方案复用价值最大的部分，新功能一个字都不动。

## 关键决策

| 决策 | 取舍 |
|---|---|
| 图片试卷**造一个假的文字层**，不新写切题 | 切题那套（锚点打分 + 题数对账）在 9 份卷子上打磨过，是这条链最硬的正确性防线，不能因为换了输入就扔掉 |
| 图片试卷跑到 ③ 讲解为止 | 动画要 ④⑤ 的完整投入，而诊断的「怎么提升」有讲解就已经立得住 |
| 答案两个来源：卷子自带 + 老师另传 | 覆盖「教师用卷」和「答案单发一张」两种真实情况 |
| **不做「页面上手改标准答案」** | 老师明确没要。**代价见下** |
| 一次传完，撞名不自动复用 | 老师不用懂两条链；但同名不同卷会静默判错人，所以 409 要带摘要让老师选 |
| 答题卡是**独立答题卡**（题号 + 作答区） | 版面干净、题号明确，Ⓑ 的难度从「分清印刷体与手写」降回「认手写内容」 |
| 答题卡未批改，系统自动阅卷 | 老师不用先批一遍，代价是「哪题错」从事实变成推断，必须配红绿灯 |
| 知识点用内置受控词表 | 名字统一才能聚合、才能说「这个点错了 2 次」；代价是要维护词表 |
| 逐题原图对照 + 老师可改判 | 这是本功能唯一的红绿灯，跟 `mathvlm.py`「原图始终保留」同源 |
| 整页一次读，判错的再裁块复读 | 便宜的筛子排在贵的前面，跟 ④c 排在 ④ 前面同源 |
| 不引 sympy 做符号等价 | 它解析带单位带下标的 LaTeX 会**静默**判错，正是本项目最怕的错 |

**「不能改标准答案」的代价，写在这里免得以后忘了为什么。** ②c 抽错一道答案，会让**所有做对这道题的学生都被判错**，凭空造出一个假的薄弱知识点。老师能看见（原图对照就在旁边），但他只能对**这一个学生**改判这一题；下一个学生传上来，还会栽在同一道题上。这是一处已知的、会重复发生的返工，本期有意不修。真要修，最小出口是让老师改 `questions.ref_answer` 一列。

## 架构：两条链，一个交汇点

```
试卷侧（一份卷子跑一次，之后所有学生复用）

  PDF    ─→ ① ingest ──────────────┐
                                   ├─→ doc.json ─→ ② 切分 ─┬─ ②b 公式 → ③ 解题 → ③b 目录 → ③c 知识点 ← 新增
  图片×N ─→ Ⓟ pages ─→ Ⓘ imgdoc ──┘        ↑              │
                       ↑                  两种输入          └─ ②c 标准答案抽取                      ← 新增
                     新增                 在这里汇合

  ④c → ④ → ④b → ⑤ → ⑥ → ⑦     照跑不动，但**只有 PDF 卷进这里**

                    题目 · 标准答案 · 知识点标签 · 讲解 ·（PDF 卷还有动画）
                                    │
答题卡侧（每个学生一次）              ▼
    Ⓟ pages  → 页面图（与试卷侧共用同一个模块）
    Ⓑ 读答案 → 整页一次拿到 [题号, 框, 最终作答]
    Ⓒ 判对错 → 代码为主；判错的裁块复读一次
    Ⓓ 出报告 → 错题 → 知识点 → 薄弱点排序 → 接讲解与动画
```

两条链解耦的理由：知识点标签、标准答案、讲解、动画都是**这份卷子的属性**，与哪个学生做的无关。答题卡那条链只读试卷侧的数据，不写。

`doc.json` 是整个设计的枢纽：**两种输入在这里汇合，之后所有阶段不知道也不需要知道原始输入是 PDF 还是照片。**

新增的两个试卷侧步骤位置按成本排（延续 ④c 排在 ④ 前面那条）：

- **②c 标准答案抽取**：只依赖 `doc.json`，与 ②b／③ 并行，不动 `segment.py`。
- **③c 知识点标注**：整卷一次调用。放在 ③ 之后是因为用得上解法 —— 知道这道题怎么解的，比只看题干更判得准它考什么。

**白捡的红绿灯**：②c 抽出的老师答案与 ③ 的 AI 答案比对一次，不一致就在页面标出来。要么 AI 解错了，要么那份答案有误。两份数据都已在库里，这条不额外花钱，却同时给 ③ 加了一层校验，并防止拿一份错答案去判学生对错。

## 摄入层：三种输入，一个规范化入口

现在有三批图要进来（试卷图、答案图、答题卡图），它们**前半段完全一样**。写三遍必然写歪，抽成一个模块：

| 模块 | 职责 | 用在哪 |
|---|---|---|
| `pipeline/pages.py` | 一批文件（图片或 PDF）→ 规范化页面图 + 页序 | 三条链共用 |
| `pipeline/imgdoc.py` | 页面图 → `doc.json` | 试卷侧、答案侧 |
| `pipeline/sheet.py` | 页面图 → 逐题作答 | 答题卡侧 |

### Ⓟ `pages.py`

- **PDF** → 逐页渲染（这段代码 `ingest.py` 里现成，复用）
- **图片** → 按 EXIF 转正（横过来的照片模型认不出题号），按**文件名自然排序**
- **两档分辨率**：300dpi 供裁块，150dpi 存图。`mathvlm.py` 就是这个配比
- 进 `assets`，`rel_path` 带前缀区分用途（`paper/pNN.png`、`answer/pNN.png`、`sheets/<sheet_id>/page/pNN.png`）
- **按图片内容哈希缓存**，跟 ②b 同源：重传同一张不重复烧钱

**页序不靠拖拽靠对账。** `IMG_001…` 通常就是拍摄顺序，先按文件名排。排错了**不会静默** —— `anchors.py` 的 D2 要求题号从 1 逐 1 递增，页序乱了题号序列当场断，② 的题数对账报 warning，页面提示老师调整。拖拽只是让老师**能**改，对账才让老师**知道要**改；后者更值钱，先做后者。

**跨图题不用新机制。** ② 本来就处理跨页题（`pages: [起, 止]`）。页序对了，跨图题就是跨页题。

### Ⓘ `imgdoc.py`（图片试卷的核心）

逐页问 VLM 要「行文字 + 行框 + 图框」，拼成与 pypdf 同构的 spans：

```json
{"text": "3.如图所示，质量为m的物块…", "x": 60.7, "x1": 401.4, "y": 503.9, "yt": 519.0, "size": 10.5, "ok": true}
```

写出 `doc.json`，之后 ② 切分、②b 公式、③ 解题**一个字不改照跑**。

三条约束：

1. **公式要朴素线性写法，不要 LaTeX。** ② 的正则是照着「PDF 文字层里公式本来就烂」写的，塞 `$...$` 进去反而破坏切题。LaTeX 交给 ②b 补 —— 图片卷和 PDF 卷在这件事上走同一条路。
   这不是将就：②b 存在的全部理由就是「文字层的公式不可信」，而 OCR 出来的公式同样不可信。**同一个病，同一副药，不用新发明。**
2. **`doc.json` 加 `source_kind: pdf | images`**，下游据此知道坐标是估出来的。
3. **认不出的行照实写 `ok: false`**，不许拿上下文补一个通顺的句子。`ok` 这一列 pypdf 路径上已经有了，含义一致。

**插图是这条路唯一真正新增的判据。** PDF 卷靠 (页, y) 把内嵌图归到题上；图片卷只有 VLM 给的框，裁歪了题干就是残的，而 ③ 解题看不见图会回 `NEED_FIGURE`。这是方案甲的主要风险，靠下面第 3 条兜底。

### 三道红绿灯（都不额外花钱）

1. **题数对账照跑。**「本题共 N 小题」对不上、D2 题号断档，都进 `warnings`，页面必须显示。转写本身没有真值可比，这是唯一的客观校验。
2. **整页渲染图始终保留、挂在题目旁。** 跟 ②b「原图始终保留」同源。转写错了，老师一眼看得见。
3. **`NEED_FIGURE` 不许吞。** ③ 说它需要图而图没归上，页面就写「这道题的图没归上，讲解未生成」，不拿一段瞎解的讲解糊过去。

### 为什么不走另外两条路

- **VLM 整页直出题目（跳过 ②）**：最省事，但切题从「纯代码可复现」退成「模型说了算」。跨页题、串号、漏题全靠模型自觉，题数对账没了，`--strict` 也没了。这恰好是本项目一直在防的那类错 —— 错了看不出来。
- **传统 OCR（PaddleOCR 等）**：坐标最准，但中文物理卷的公式区吐乱码，乱码污染锚点打分；补完公式还是要叠一层 VLM。等于绕一圈回到甲，还多一个部署依赖。

## 数据模型

写法沿用 `schema.sql` 现有分界线：产品数据进列，管线中间量进 jsonb。

```sql
-- 一份答题卡 = 一个学生的一次作答。
-- **不建 students 表**：范围定死单人、不做班级，学生就是老师随手填的一个标识。
-- 建了表就要配增删改查和「同一学生的历次考试」，那是另一个功能。
CREATE TABLE answer_sheets (
  id            bigserial PRIMARY KEY,
  paper_id      bigint NOT NULL REFERENCES papers(id) ON DELETE CASCADE,
  owner_id      bigint REFERENCES users(id) ON DELETE SET NULL,
  student_label text,
  n_pages       int NOT NULL DEFAULT 0,
  created_at    timestamptz NOT NULL DEFAULT now(),
  -- 老师改判会 touch 它。诊断过没过期，拿它跟 diagnoses.created_at 比 ——
  -- 跟 papers.assembled_at 判 out.html 旧没旧是同一个套路
  updated_at    timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE sheet_answers (
  id          bigserial PRIMARY KEY,
  sheet_id    bigint NOT NULL REFERENCES answer_sheets(id) ON DELETE CASCADE,
  -- **可空**：认出了题号但卷子里没这道题（串号、学生多写一道）。
  -- 挂不上就是挂不上，页面明说，不许猜一个最近的题号安上去
  question_id bigint REFERENCES questions(id) ON DELETE CASCADE,
  n           int  NOT NULL,
  raw_text    text,        -- 模型认出的最终作答，**原样**，不加工
  norm        text,        -- 归一化后的形式，判定拿它比
  crop_rel    text,        -- 原图切片的 assets.rel_path
  box         jsonb,
  page        int,
  read_conf   text,        -- 模型自称的把握 high/medium/low
  reread      boolean NOT NULL DEFAULT false,

  -- **verdict_by 才是红绿灯** —— 同一个「错」，代码判的和模型判的
  -- 可信度差一个量级，页面必须分得出来
  verdict         text,    -- right | wrong | blank | unsure
  verdict_by      text,    -- code | model | teacher
  verdict_why     text,

  -- 老师改判**单独一列，不覆盖系统原判**。留着原判才看得出系统错在哪，
  -- 也才撤得回来。读取一律走 store 里那一个 COALESCE 函数，不让每个
  -- 调用点各写一份 —— api.ts 那次 401 广播就是这个教训
  teacher_verdict text,

  UNIQUE (sheet_id, n)
);

-- 知识点受控词表。code 是稳定代号而不是自增 id：词表是版本管理的种子
-- 数据，重灌一次自增 id 就全漂了，code 不会。
CREATE TABLE kp_catalog (
  code    text PRIMARY KEY,
  chapter text NOT NULL,
  name    text NOT NULL,
  aliases jsonb NOT NULL DEFAULT '[]'
);

CREATE TABLE diagnoses (
  sheet_id   bigint PRIMARY KEY REFERENCES answer_sheets(id) ON DELETE CASCADE,
  weak_kps   jsonb NOT NULL DEFAULT '[]',
  advice     jsonb NOT NULL DEFAULT '[]',
  model      text,
  created_at timestamptz NOT NULL DEFAULT now()
);

ALTER TABLE questions ADD COLUMN IF NOT EXISTS kps            jsonb NOT NULL DEFAULT '[]';
ALTER TABLE questions ADD COLUMN IF NOT EXISTS ref_answer     text;
-- paper | answer_file | none —— 三个来源要分得出来，页面上「这份答案哪来的」是老师判断可信度的依据
ALTER TABLE questions ADD COLUMN IF NOT EXISTS ref_answer_src text;

-- pdf | images。决定这份卷子跑不跑 ④⑤⑥，也决定进度怎么算（见下）
ALTER TABLE papers    ADD COLUMN IF NOT EXISTS source_kind text NOT NULL DEFAULT 'pdf';
```

**没有 `state` 列**，有意为之。现有 `papers` 也没有 —— 进度由 `stage_of` 从库里的计数反推。答题卡链同理：有没有页面图 → 有没有 `sheet_answers` → 有没有 `verdict` → 有没有 `diagnoses`。多一个状态列就多一个会跟事实不同步的东西。

**`kps` 用 jsonb 存 `[{code, why}]` 而不是关联表**：范围是单人单卷十几道题，聚合在应用层做就够，不需要 `GROUP BY`。代价是 code 没有外键保护，所以 ③c 写入时要拿 `kp_catalog` 校一遍，挂不上的明说挂不上。将来真要跨卷追踪同一学生，再补关联表。

**原图切片走现有 `assets` 表，一个字都不改**：`paper_id` 填答题卡所属的卷子，`rel_path` 用 `sheets/<sheet_id>/q7.png` 带前缀 —— `UNIQUE (paper_id, rel_path)` 仍成立，存储层抽象（local/minio 切换不影响前端 URL）和 `api.py` 的资产代理全都白拿，删卷子时切片跟着 CASCADE 掉。

## 图片卷没有动画，这件事会咬人

图片卷不进 ④c/④/④b/⑤/⑥。由此带来一个**不写清楚一定会踩的坑**：

`stage_of` 是从库里的计数反推进度的。图片卷的 `scenes` 永远是 0，会被判成「还没跑完」—— 进度带永远转、`done` 永远是 false、列表页永远显示「生成中」。

所以：

- **`stage_of` 必须按 `source_kind` 分支**，图片卷的终点是 ③c 而不是 ⑦。
- 试卷页那排阶段标志，图片卷把 ④⑤⑥ 显示成**「不适用」而不是「未完成」**。灰掉并写清楚，不要让老师以为卡住了。
- 诊断报告的「怎么提升」原本挂三样（错题原图 / 讲解 / 动画），图片卷只有两样。

## 试卷侧新增

### ②c 标准答案抽取

两个输入，**单独传的那份优先** —— 老师专门传了一份答案，说明他更信这份。

| 来源 | 怎么抽 | `ref_answer_src` |
|---|---|---|
| 老师另传的答案文件 | 走 `pages`→`imgdoc`/`ingest` 得到自己的 `doc.json`，按题号切 | `answer_file` |
| 卷子自带 | 从题目的 `doc.json` 里找「参考答案」段落起点，按题号切开 | `paper` |
| 都抽不到 | —— | `none` |

纯代码优先：按题号切。切不出来（版式特殊、答案分散在每题后面）才叫一次模型兜底。

`ref_answer_src='none'` 的题在 Ⓒ 一律判 `unsure`，并写明原因是**卷子里没有答案，不是学生的问题**。不留空猜。

**两份都有且对不上 → 页面标出来。** 又一个白捡的红绿灯，一分钱不花。

### ③c 知识点标注

整卷一次调用。输入每题的题干 + ③ 的解法 + 词表全文，输出 `[{n, kps:[{code, why}]}]`。

三条约束：

- **只能从词表挑 code**，编出来的一律丢掉
- 一道题最多挂 3 个。挂满等于没挂
- `why` 是针对**这道题**的一句话（「用动量守恒求碰后速度」），不是知识点定义

挂不上就 `kps` 留空，页面明说「这道题没挂上知识点」。不硬塞一个最接近的 —— 塞进去的标签会污染薄弱点统计，而且没人看得出来它是塞的。

词表种子放 `pipeline/kp_seed.json`，跟代码一起版本管理，两级（章 → 知识点），约两三百条覆盖高中物理：

```json
{"code": "mech.newton2",  "chapter": "力学",   "name": "牛顿第二定律",
 "aliases": ["牛二", "动力学基本方程", "F=ma"]}
```

`aliases` 是给 ③c 挂标签时容错用的。

## 答题卡侧

### Ⓑ 读答案

整页图进（`pages.py` 给的 150dpi 图），`[{n, box, answer, conf}]` 出。

**答题卡是独立答题卡**：只有题号和作答区，没有题干。版面干净，题号明确，不需要先分清「哪些是印刷体、哪些是学生写的」。

提示词上三条从 `solve.py` 的经验来 —— 它记着「DeepSeek 老老实实回 `NEED_FIGURE` 而不是编一个读起来合理的答案」，**给模型一个明确的认输出口，比反复叮嘱别猜有用得多**：

1. 认不出就回 `unreadable`，明写「认不出比猜错好」
2. **题号必须是图上真实认出来的**，不许按顺序编。没看到题号回 `n: null` 加位置描述 —— 这是防串题的主要手段
3. 空白回 `blank`，不许拿附近的字凑

拿到 `box` 之后**当场按框裁出小图存进 `assets`**（`sheets/<sheet_id>/q7.png`），写进 `sheet_answers.crop_rel`。这一步不能推迟到「老师要看时再裁」：页面图有可能已经被清理，而原图切片是本功能唯一的红绿灯，它必须和判定一起落库。

跨页大题（写不下续到下一页）：同一题号在多页出现按页序拼接，`box` 存第一处。

### Ⓒ 判对错

`verdict` 只有四个值，判定条件不许有第五种解释：

| verdict | 什么时候 | 计入薄弱统计吗 |
|---|---|---|
| `right` | 归一化后与标准答案相等，或模型判等价 | 进分母 |
| `wrong` | 归一化后不等，或模型判不等价 | 进分子和分母 |
| `blank` | Ⓑ 回了 `blank`，该题没有作答 | **都不进** |
| `unsure` | Ⓑ 回了 `unreadable`（认不出），或该题没有标准答案（`ref_answer_src='none'`） | **都不进**，但要在报告里单独列出来 |

`blank` 和 `unsure` 都不进统计，但含义不同，页面上要分开显示：前者是学生没写，后者是**系统没能力判**。把后者混进「错」等于拿系统的无能去当学生的薄弱点。

**确定档（`verdict_by='code'`）**

- 选择题：归一化成大写字母集合，与标准答案比集合相等
- 数值：`1.5` / `3/2` / `1.5m/s` / `1.5 m/s` 提取数值和单位后按相对误差比
- 表达式：LaTeX 归一化（去空格、`\dfrac`→`\frac`、`·`→`\cdot`）后字符串比

**不引 sympy 做符号等价。** 它解析带单位带下标的中文物理题 LaTeX 容易翻车，而翻车的样子是「静默给出一个错误的等价判断」—— 学生答对的题被判错，凭空造出一个薄弱知识点，页面上一切看起来正常。代码档只做**不会静默出错**的两件事：归一化字符串比、数值比，它们要么明确相等要么明确不等，没有第三种。

**推断档（`verdict_by='model'`）**：形式差得远、代码判不了的，给标准答案与学生作答，**只问「这两个是不是同一个答案」，不问对错**。页面上与代码判的区分开。

**判错的题一律裁块复读一次。**

理由是代价不对称：判对了没人受损；**判错了会凭空造出一个假的薄弱知识点**，而薄弱知识点是本功能唯一的产出。错题通常是少数（十几道错三五道），复读很便宜。复读用 300dpi 单题单次调用，问题更聚焦。两次结果不一致以复读为准，但**两次都留着**，页面标「复读后改判」。

复读的四个触发条件：`verdict='wrong'`、`verdict='unsure'` 且原因是认不出、`read_conf='low'`、题号挂不上卷子。复读只跑一次，复读后仍认不出就维持 `unsure` —— 不无限重试，读不出来是事实，说出来比反复烧钱强。

**`blank` 不是 `wrong`。** 卷子最后几道大题空白多半是时间不够而不是不会。混成「错」会把最后几个知识点全标成薄弱 —— 全是假的。空白不计入薄弱统计，报告里单独说一句「有 3 道题空白，未计入诊断」。

### Ⓓ 诊断

**薄弱点按比例排，不按错题数**：`错的道数 / 该知识点在这份卷子上的总道数`。错 2/2 比错 2/5 严重得多。

- 代码判错的和模型判错的分开计数，报告写「其中 1 道是推断判定」
- `blank` 和 `unsure` 都不进分子也不进分母（见 Ⓒ 的判定表）
- 某知识点在这份卷子只出现一道且错了 → 标「只考了一道，样本不足」。一道题撑不起「你这个点弱」这个结论，但值得提一句

**「怎么提升」定死结构**，每个薄弱知识点下挂**已经存在于库里**的东西：

1. 这次错的那几道题 —— 题干 + 学生作答原图切片 + 标准答案
2. 现成的逐题讲解 —— `solutions.steps`、`key_facts`、`assumptions`
3. 现成的动画 —— `scenes` 里过了门禁的那些（**PDF 卷才有**）

模型只负责最后一小段：把这几道题串起来说一句「你这几道都栽在同一处……」。**这段话里必须出现具体题号，没有题号的建议直接丢掉重生成。** 「多练习动量守恒相关题目」这种话写出来和没写一样。

## 上传入口：一次传完

`POST /api/diagnose`，multipart 三个投放区：

| 字段 | 必填 | 内容 |
|---|---|---|
| `paper[]` | 是 | 题目：图片×N 或一个 PDF |
| `answer[]` | 否 | 单独的答案文件。**不传就表示答案在题目里** |
| `sheet[]` | 是 | 答题卡图片×N |
| `student` | 否 | 老师随手填的标识 |

后台一条任务串两段：

- 试卷段：PDF 走 `ingest`（它自带逐页渲染，不必再过 `pages`）；图片走 `pages` → `imgdoc`。之后一律 ② → ②b → ②c → ③ → ③b → ③c
- 答题卡段：`pages` → Ⓑ → Ⓒ → Ⓓ

进度带和 `failedStage` 直接复用现有机制，答题卡四步追加在阶段条后面。**第一份要等整条试卷段（几十分钟），页面上必须说清楚正在等什么** —— 现有进度带够用。

### 撞名不自动复用

老师传第二个学生时卷名必然撞。现有那道 409 闸会把他挡在门外，什么也做不了；但反过来自动认成同一份卷子也不行 —— **两份不同的卷子重名，会静默拿错答案去判一个学生**。

所以 409 要**带上已有卷子的摘要**（哪天传的、多少题、`source_kind`），前端给两个出口：

- 「用已有的这份」→ 跳过试卷段，只跑答题卡段
- 「这是另一份卷子」→ 加后缀另建

卷名怎么定：PDF 沿用现有（文件名）；图片卷取首页转写出来的标题行，取不到就用第一个文件名。

**同卷同学生不许同时跑两条链**，复用 `CLAIMS` + 409 那道闸。

## 页面

入口在试卷页 —— 答题卡挂在某份卷子上，不是独立的东西。`PaperView` 下面多一块「学生答题卡」列表，点开是诊断报告。

```
张三 · 2025年高考北京卷物理真题          [重新诊断]

逐题  1 ✓  2 ✓  3 ✗  4 ✓  5 —  6 ✗  7 ✓ …     ← ✗ 默认展开，✓ 折叠
      ┌──────────┐  认出的作答：B
      │ 原图切片  │  标准答案：  C  （来自：老师上传的答案文件）
      │（学生手写）│  判定：错 · 代码判定 · 复读后改判
      └──────────┘  [改判为对]

薄弱知识点
  1. 动量守恒定律  错 2/2 · 力学
     这次错的：第3题、第6题
     「两道都栽在同一处：碰后动量写成了标量相加…」
     ▸ 第3题 讲解 + 动画    ▸ 第6题 讲解

  2. 法拉第电磁感应定律  错 1/3 · ⚠ 其中 1 道是推断判定

有 3 道题空白，未计入诊断（第14、15、16题）
判定与建议由 AI 生成，未经人工审核 —— 逐题原图就在上面，请对照
```

四条硬约束：

- **原图切片必须挨着判定，不能藏进二级页面**。老师一眼能校对是本功能唯一的红绿灯，藏一层等于没有
- **`verdict_by` 要显示**（代码判定 / 推断判定 / 老师改判）
- **`ref_answer_src` 要显示**。标准答案是卷子里抽的还是老师传的，直接影响老师对一次判错的信任度
- **改判后诊断标为过期，不自动重跑**。连改五题跑五次模型不合理；但也不能默默显示旧报告 —— 明确标「判定改过了，这份诊断是旧的」，配「重新诊断」按钮。与 `assembled_at` 判 `out.html` 旧没旧同一模式

图片卷额外：整页渲染图挂在题目旁（转写的红绿灯），④⑤⑥ 三格显示「不适用」。

## 失败处理

分界线：**缺一条数据就说缺这一条，不要让整份报告消失**；反过来，读不出任何东西就得老实失败，不能拿一份九道题的残报告冒充完整诊断。

| 情况 | 处理 |
|---|---|
| 传的不是 PDF/图片 | 400，当场拒 |
| 题目一批里混进了答题卡 | 不特判。②切不出题会报 warning，老师看得见 |
| `imgdoc` 转写后 ② 一道题都切不出来 | **失败**。多半拍歪了或传错文件，提示重拍 |
| ② 切出的题数与「本题共 N 小题」对不上 | **不失败**，warning 列出差多少，提示可能是页序乱了 |
| 某题的图没归上，③ 回 `NEED_FIGURE` | **不失败**，该题标「图没归上，讲解未生成」，整页原图就在旁边 |
| 整页读回来一道题都没有（答题卡） | **失败**。多半拍歪了或传错文件，提示重拍 |
| 卷子 16 题只认出 9 题 | **不失败**，警告「有 7 道题没在答题卡上找到」并列出题号 |
| 认出的题号卷子里没有 | **不失败**，`question_id` 留空，单独列出来 |
| ②c 没抽出标准答案 | 该题标 `unsure`，写明「这份卷子没有标准答案」，不算错也不算对 |
| 一道题都没错 | 不编薄弱点，直接说「这次全对」 |
| 建议里没有题号 | 重生成一次；仍没有就只展示错题和讲解，**不展示建议** |

## 测试

- **判对错的归一化是纯函数，要测厚** —— 选择题字母集合、数值+单位提取、LaTeX 归一化。这是本功能里唯一能真正自动测的部分
- **`imgdoc` 有现成的真值**：把库里九份 PDF 卷渲染成图片，走 `imgdoc` 再切一遍，跟 PDF 路切出的 `questions.json` 比。题号集合、题数、题干长度分布对不对，全自动，不用人看。**这是整个方案里最值钱的一个测试**，它把「VLM 转写准不准」从主观判断变成了可回归的数字
- ②c 答案抽取、③c 知识点挂标签：拿库里现有九份卷子当样本跑，人工核对
- 端到端：需要真实的手写答题卡样本

## 实施顺序

**本功能有两个在拿到真实样本之前完全验证不了的风险**，都必须在建表、写 API、写页面之前探掉：

| 探针 | 跑什么 | 看什么 | 不过怎么办 |
|---|---|---|---|
| 1 | 一份拍照的卷子，只跑 `imgdoc` + ② | 切出的题数对不对、插图归对没有 | 退「VLM 直出题目」，或图片卷只收不带插图的题 |
| 2 | 一份真实手写答题卡，只跑 Ⓑ | 题号和最终作答认得对不对 | 退回「老师先批改再传」—— 那是完全不同的一条链 |

探针 1 可以**先用九份 PDF 卷渲染成图片来跑**（见「测试」那节），零成本拿到第一手数据；再补一份真照片验证拍摄噪声。

两个都能过再往下。先花一天探掉这两个，比四张表建好之后才发现地基不稳便宜得多。

风险探掉之后分四期，**每一期都要落到页面上**（只做到库和 API 不算完成）：

| 期 | 做什么 | 页面上能看到什么 |
|---|---|---|
| 一 | 词表 + ②c + ③c，`questions` 补三列 | 试卷页每题显示知识点标签和标准答案；AI 答案与卷子答案不一致的题打标记 |
| 二 | `pages.py` + `imgdoc.py`、`papers.source_kind`、`stage_of` 分支 | 拍照传上来的卷子出现在列表里，有题干、有讲解，④⑤⑥ 显示「不适用」 |
| 三 | `answer_sheets` / `sheet_answers`、Ⓑ Ⓒ、`/api/diagnose`、改判 | 一次传三样 → 逐题对错 + 原图对照 + 改判。**没有诊断也已经能用** |
| 四 | `diagnoses`、Ⓓ、薄弱点与建议 | 完整报告，接讲解与动画 |

第一期不碰图片也不碰答题卡，用库里现有九份卷子就能验证，而且它自己就有价值 —— 老师能看到这份卷子考了哪些知识点，还能发现 AI 解错的题。第二期交付的是「拍照也能传卷子」，与诊断无关也成立。第三期交付的是「自动阅卷」，不依赖诊断也成立。这样任何一期停下来，前面的都不白做。
