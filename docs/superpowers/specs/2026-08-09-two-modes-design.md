# 两种模式：解析试卷 · 答题卡诊断

> **一句话**：把「解析试卷」和「答题卡诊断」分成页面上两个并列的模式，各有各的入口、
> 各有各的库、各有各的进度口径；顺带把答题卡那条链**在页面上真正接通**（读参考答案）。

## 背景

两条链在设计上早就是两件事（`2026-08-06-answer-sheet-diagnosis-design.md` 写着
「现有的 ①②③④⑤ 一个都不进」），但在**代码和页面上仍然是一件事**：一个上传框、
一张试卷库表、一条六格进度带、一个 `stage_of` 里的 `if`。

结果是两头都不好：

| 缠在哪 | 现状 | 症状 |
|---|---|---|
| 入口 | 只有一个拖拽框、只收 PDF | 答题卡那条链**在页面上没有入口**，只能命令行跑 |
| 库列表 | 一张表混两种卷子，列是「插图/动画/告警」 | 答案卷这三列永远 0 |
| 阶段机器 | `api.py:stage_of` 一个函数里 `if sourceKind == 'answers_only'` | 加一格要改两条分支，STATUS 记着**已踩过两次** |
| 阶段标志 | 前端 `PaperView.tsx:6` 写死 6 格、`:27` 又写死一张代号映射表 | 答案卷 4 格永远灭着，`refread` 被硬塞进「① 摄入」 |
| 进度细目 | 「解题/选题/断言/自检/动画」写死 | 答案卷全 0 |
| 概览与页脚 | 「n 张图为动画」「答案、解题步骤与动画均由 AI 生成」 | 答案卷的答案是**官方参考答案**，这句话是错的 |
| 继续执行 | `POST /resume` 不看 `source_kind` | 对答案卷点下去会去跑 solve/spec/scene |

**根因只有一个**：「一共有哪几步、每步叫什么」这份清单在代码里抄了**三份**
（`stage_of` 的 return、前端 `STAGE_LABEL`、前端 `STAGE_OF_CODE`）。历史上那两次坑
——「进度带永远转」和「一格都不亮」——都是抄漏了一份。现在要多出**第二套步骤**，
不消掉这个重复，「分成两种模式」只是把 `if` 换个地方写。

## 目标

- 页面顶部两个模式：**解析试卷** ｜ **答题卡诊断**。切模式换整屏，互相看不见对方的卷子。
- 答题卡模式有**自己的上传入口**：填卷名 + 传参考答案（图或 PDF，可多张）→ 出一份卷子。
- 答题卡模式的卷子逐题显示：**标准答案 · 官方解答过程 · 知识点**。
- 两个模式**各有各的阶段清单**，且这份清单在代码里**只存在一份**（后端），前端照着画。
- 加阶段忘了登记时，**测试当场红**，不是等页面上进度带转个没完才发现。

## 非目标

- **不读学生答题卡、不判对错、不出薄弱知识点报告**。那是原设计的步二、步三。
- **不做 Ⓔ 读题干**。它卡在老师还没给的题目图片上，代码写得出、验收做不了。
  这一轮答题卡模式的题干**就是空的**，页面上要明说，不许不声不响留白。
- **不改 `segment.py` / `anchors.py` / `ingest.py` / `solve.py` / `scene.py`**。
  解析试卷那条链一个字不动 —— 这是「互不干扰」的第一层意思。
- **不改 `source_kind` 的取值**，不迁移数据。
- 不做班级、不做学生账号、不做模式之间的互转按钮。

## 关键决策

| 决策 | 取舍 |
|---|---|
| 模式 = `source_kind` 的一个**函数**，不是新加一列 | `source_kind` 说的是「原料是什么」（`pdf` / `answers_only`），模式说的是「用户在做哪件事」。现在一一对应，但概念不同 —— 将来 `answers_only` 若分化出「答案+题干」，仍属同一个模式，不必再迁一次数据 |
| 阶段清单收成一份，放后端，**下发**给前端 | 消掉三抄一。代价是 `/progress` 的返回大一点点（两个模式各 2–6 格），换来的是「加一格只改一个地方」 |
| 数据库仍共用 `papers` / `questions` | 归属、删除级联、资产存储、页面路由全都白拿；且保住原设计那条「老师补传题目直接填 `stem`」 |
| 卷名仍是**一个池子** | `papers.name` 是 `NOT NULL UNIQUE`（`schema.sql:12`），页面地址也是 `#/p/<卷名>`。两个模式重名时，第二份自动变「X (2)」，走的是现成的 `free_name` |
| 答题卡模式**不复用** `PaperView` / `QuestionCard` | 「互不干扰」的核心就是别让一个组件里塞两套话术。`PaperView` 已 491 行。共用的小件（`Latex`、`MathText`、`RichText`）继续共用 |
| 答题卡模式**复用** `GET /api/papers/{name}` | 它已经把 `questions` / `kps` / `refAnswer` / 资产 URL 都拼好了；再写一个端点等于抄一遍。只需补上漏给的 `ref_solution` |
| 上传失败时**只删这一次新建的空壳** | 重跑已有卷子失败时不能删 —— `sheet_answers` 以 `ON DELETE CASCADE` 挂在 `questions` 上，删一次会连学生的作答一起没 |

## 架构

```
                    ┌── 解析试卷 ────────────────────────────────┐
   PDF ────────────▶│ ① 摄入 ② 切分 ③ 解题 ④ 断言 ⑤ 场景 ⑦ 呈现 │
                    └───────────────────────────────────────────┘
                    ┌── 答题卡诊断 ─────────────┐
   参考答案图/PDF ──▶│ Ⓐ 读参考答案  ③c 知识点  │  ← 本轮做到这里
                    └───────────────────────────┘
                       （步二 Ⓢ/Ⓑ/Ⓒ、步三 Ⓓ 不在本轮）

   共用底层：pages.py · kp.py · grade.py · store · assets(MinIO) · 账号
```

### 模式注册表（`pipeline/modes.py`，新文件）

一个模式是一条**数据**，不是一堆散在各处的 `if`：

```python
Mode(
    code="paper", label="解析试卷",
    # None 不是「老卷子」（`source_kind` 在库上是 NOT NULL DEFAULT 'pdf'），
    # 而是「进度字典里根本没有这个键」的兜底 —— `test_stage_of.py` 的 BASE 就没有它，
    # 而那些用例必须继续判成解析试卷
    source_kinds=("pdf", None),
    stages=[("ingest","① 摄入"), ("segment","② 切分"), ("solve","③ 解题"),
            ("spec","④ 断言"), ("scene","⑤ 场景"), ("assemble","⑦ 呈现")],
    # stage_of 可能返回的每个代号 → 落在上面哪一格。子步骤（③b/③c/④b/④c）
    # 没有自己的格子，归到所属大阶段；ingest/segment 只由 failedStage 走到
    cell_of={"ingest":"ingest", "segment":"segment",
             "solve":"solve", "outline":"solve", "kpmark":"solve",
             "pick":"spec", "spec":"spec", "check":"spec",
             "scene":"scene", "assemble":"assemble"},
    needs_artifact=("scene", "assemble"),   # 这两格另有「产物在不在」的事实
    stage_of=_stage_of_paper,               # 纯函数，只读 progress 那个 dict
)

Mode(
    code="sheet", label="答题卡诊断",
    source_kinds=("answers_only",),
    stages=[("refread","Ⓐ 读参考答案"), ("kpmark","③c 知识点")],
    cell_of={"refread":"refread", "kpmark":"kpmark"},
    needs_artifact=(),
    stage_of=_stage_of_sheet,
)
```

`api.py` 里 `stage_of(pg)` 变成一行分发：`modes.of(pg["sourceKind"]).stage_of(pg)`。
两个纯函数各自独立，不再共享那个 `if`。

**这份清单是唯一的一份。** 前端删掉 `STAGE_LABEL` 和 `STAGE_OF_CODE`，改从接口读。

### 门禁：加阶段忘登记，测试当场红

一条遍历所有模式的测试：

- `stage_of` 里出现的每个代号，都必须在这个模式的 `cell_of` 里；
- `cell_of` 的每个值，都必须是这个模式 `stages` 里真实存在的一格；
- 每个模式都必须能返回 `done`。

代号清单从 `stage_of` 的源码里抓（`re` 扫 `return "xxx"`），不靠人手抄第二遍 ——
手抄的话这条门禁自己就成了第四份清单。

**它在最需要的时刻触发**：历史上出事的时刻正是「往管线里加一步」，而加完这一步
一定会改 `stage_of`，改完跑测试就红。不是等某份卷子在页面上转个没完才发现。

### 接口

**`GET /api/papers`** 加一个可选参数 `mode=paper|sheet`，不给就全给（命令行/运维用）。
每行多两个数供答题卡模式的列头用：`withSolution`（带官方解答的题数）、`kps`（挂上知识点的题数）。
`store.list_papers` 相应多返回 `source_kind` 与这两个计数。

**`GET /api/papers/{name}` 与 `/progress`** 多带一块 `mode`，**每一格连状态一起给**：

```json
"mode": {
  "code": "sheet", "label": "答题卡诊断",
  "stages": [{"code":"refread", "label":"Ⓐ 读参考答案", "state":"done"},
             {"code":"kpmark",  "label":"③c 知识点",   "state":"now"}]
}
```

`state` 的五个值沿用现在前端那五种：`done` / `now` / `todo` / `fail` / `empty`
（跑过去了但没产物）。

**为什么连状态一起算，而不是只给清单让前端自己判**：`web/` 里**一个测试都没有**
（`package.json` 没有测试框架，436 条测试全是 Python）。而「哪一格什么状态」正是
历史上出过两次错的那段逻辑 —— 三段切分、`NEEDS_ARTIFACT` 两处例外、失败只画在
它自己那一格。把它留在前端等于把最容易错的一段放在唯一没有测试的地方。

搬到后端之后 `PaperView.tsx` 里 `STAGE_LABEL`、`STAGE_OF_CODE`、`NEEDS_ARTIFACT`、
`stageStates` **四个东西一起删掉**，前端只剩 `map` 一遍照着画。

`/progress` 也要给这一块（它是每 3 秒轮询的那个），所以「产物在不在」的两条事实
（⑤ 有没有通过门禁的动画、⑦ 的 out.html 还在不在磁盘上）也要在 `/progress` 里算 ——
多一次 `os.path.exists`，可以忽略。

**不在这一轮引入前端测试框架。** 那是另一个决定，不该顺手夹带；这里选的是把逻辑
挪到已经有测试的那一侧。

**`POST /api/answer-papers`**（新）—— multipart：

- `name`：卷名，必填，走现有的 `safe_name` + `free_name`（含 `CLAIMS` 占用）。
  **填一个自己已有的答题卡卷名 = 重跑那份卷子**（口径与 `/api/upload` 一致：
  `put_answer_question` 是 upsert，重跑只更新答案与解答两列，不碰 `stem` / `kps`）；
  撞上**别人**的卷名才改名。
  **撞上自己一份解析试卷的卷名：也改名，不许就地转模式**（见下）
- `files`：一到多个，后缀须在 `pages.IMG_EXT` 或 `.pdf`（口径与 `pages.normalize` 一致），
  总字节 ≤ 80 MB（与 `/api/upload` 同一条线）
- 闸门：`active_job_for(name) or pipeline_running(name)` → 409
- 后台线程：`create_answers_paper` → `refread.py <卷名> <图...>` → `kpmark.py <卷名>`
- 与 `/api/upload` 共用 `JOBS`、`job_log`、`run_step`、`step_env`

**`GET /api/papers/{name}` 的题目投影补一个字段**：`refSolution`（`ref_solution`）。
它现在库里有、`get_paper` 也查了，但投影里漏了 —— 官方解答过程是这个模式最值钱的
产出，而它到不了页面。

### 顺带补的四个洞（不补这一轮走不通）

1. **答题卡链没法自己开张。** `store.create_answers_paper` 全仓库只有测试在调；
   `put_answer_question` 要求 `papers` 行已存在（`store.py:583`），所以
   `python pipeline/refread.py 新卷名 图…` 会报「库里没有『新卷名』」。
   **改法**：`refread.py` 的 `main()` 加 `--create`（新建卷子），API 那条路直接调
   `create_answers_paper`。不让 `read()` 自己隐式建 —— 隐式建会把打错的卷名变成一份新卷子。
2. **`PIPE_RE`（`api.py:799`）里没有 `refread`**，也没有 `stemread`（将来的 Ⓔ）。
   于是「这份卷子在跑吗」对答题卡链永远答 false，上传闸门是漏的。**改法**：加进去。
3. **`ref_solution` 到不了页面**（见上）。

### 第四个洞：`create_answers_paper` 会**静默把一份解析试卷改成答题卡卷子**

`store.py:544-546` 那条 `ON CONFLICT (name) DO UPDATE SET … source_kind='answers_only'`
不看原来是什么。今天它只被测试调，所以没出事；这一轮一接上上传入口，就成了
**这次改动最该挡住的那种干扰** —— 老师在答题卡模式随手填了一个和自己某份高考真题
一样的卷名，那份跑了一小时的解析试卷会当场变成答题卡卷子：`stage_of` 改走两格链、
解法和动画还在库里却一格都不显示，而**没有任何一句话提示发生了什么**。

**改法**：`create_answers_paper` 加一道 `WHERE` —— 只在「不存在」或「已经是
`answers_only`」时才写；命中一份 `pdf` 卷子就抛。API 那层在挑卷名时就把这种情况
算进 `free_name`，用户看到的是「卷名自动改成了 X (2)」，不是一条报错。

## 页面

### 顶部

```
exam-explainer                                    jerry@…   退出
────────────────────────────────────────────────────────────
 【 解析试卷 】   答题卡诊断
────────────────────────────────────────────────────────────
```

hash 路由分两支：`#/paper`、`#/paper/<卷名>`、`#/sheet`、`#/sheet/<卷名>`。
**模式写进地址**，刷新不丢、链接可分享。地址为空时默认落到**解析试卷** ——
它是现有用户唯一在用的那一个，默认换掉等于把所有人的首页改了。

老地址 `#/p/<卷名>` 要继续能开 —— 命中时去问一次这份卷子属于哪个模式，再换到对应
的新地址。旧链接直接失效是不可接受的。

### 解析试卷（不动）

上传框、试卷库（试卷 / 进度 / 题数 / 插图 / 动画 / 告警）、`PaperView` 全部照旧。
唯一的变化是阶段带改从接口读清单 —— 画出来的东西一模一样。

### 答题卡诊断（新）

```
卷名  [2025-2026高二物理期末            ]
┌────────────────────────────────────────┐
│  把参考答案拖到这里（照片 / 扫描图 / PDF，可多张） │
└────────────────────────────────────────┘

答题卡库
卷名 | 进度 | 题数 | 带解答 | 挂知识点
```

详情页（新组件 `SheetView` + `AnswerQuestionCard`）：

```
2025-2026高二物理期末
Ⓐ 读参考答案 ✓    ③c 知识点 ✓            26 题 · 3 题带解答 · 24 题挂了知识点

第 11 题
  标准答案   2BIL / MP
  官方解答   由安培力公式 F=BIL…            ← ref_solution，大题才有
  知识点     安培力 · 磁场
  题干       这道题的题干还没有（要传题目图才读得到）

第 1 题
  标准答案   D
  官方解答   参考答案上这道题没有解答过程    ← 「没有」和「没读出来」是两句话
  知识点     （没挂上知识点）
```

四条硬约束：

- **「参考答案上没有」和「我们没读出来」必须是两句不同的话。** 参考答案的版式就是
  只有大题给详解（2026-08-08 实测），把它说成「读取失败」是冤枉这份材料。
- **题干为空要明说**，不留白。
- **页脚免责换掉。** 标准答案与官方解答来自老师给的参考答案，**不是 AI 生成的**；
  AI 生成的只有知识点标签。现在那句「答案、解题步骤与动画均由 AI 生成」出现在这里是错的。
- **不显示动画、不显示「继续执行」以外的重跑按钮。** 这个模式没有 ⑤。

### `resume` 按模式收口

`POST /resume` 现在不看模式。改成按模式分发：`sheet` 模式的「继续执行」只会接着跑
Ⓐ/③c，不会去碰 solve/spec/scene。

## 失败处理

| 情况 | 处理 |
|---|---|
| 卷名空 / 只剩非法字符 | 400，当场拒 |
| 一个文件都没有 | 400 |
| 文件不是图片也不是 PDF | 400，说清收哪些格式 |
| 同名卷子正在跑 | 409，与 `/api/upload` 同一句话术 |
| 卷名撞上自己一份**解析试卷** | **不覆盖、不转模式**：自动改成「X (2)」并在页面上说出来 |
| Ⓐ 某一页读失败 | **不失败**：`refread.read` 已经把失败页记下来并报出来，只有一页都没成才算失败 |
| Ⓐ 一道题都没读出来 | 任务 `error`；**这一次新建的空壳卷子删掉**，重跑已有卷子则保留（见「关键决策」） |
| ③c 挂不上知识点 | 不失败。页面逐题写「没挂上知识点」，不塞占位标签 |
| 题号出现结构性矛盾（既有「15」又有「15(1)」） | 不失败，`refread` 已有告警，**要显示在页面上**，不能只打在日志里 |
| 旧地址 `#/p/<卷名>` 指向的卷子不存在 | 退回解析试卷模式的库，给一句「这份卷子不在了」 |

## 测试

**纯函数优先，先写测试再写实现，一个任务一个 commit。**

| 测什么 | 怎么测 |
|---|---|
| 模式清单门禁 | 遍历所有模式：`stage_of` 里的代号 ⊆ `cell_of` 键；`cell_of` 值 ⊆ `stages` 代号；每个模式都能到 `done` |
| `paper` 模式 `stage_of` 不回归 | 现有 `test_stage_of.py` / `test_progress.py` **一个字不改**就要绿 |
| `sheet` 模式 `stage_of` | 现有 `test_stage_answers_only.py` **一个字不改**就要绿 —— `api.stage_of` 保留原签名，只是变成一行分发 |
| 每一格的状态 | `modes.cell_states()` 纯函数：三段切分、`empty`（跑过没产物）、失败只落在自己那一格、轮询还没回来时的兜底 |
| 上传入口 | 卷名校验、格式校验、撞名改名、409 闸门、Ⓐ 全失败时删空壳、重跑失败时**不**删 |
