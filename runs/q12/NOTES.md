# q12 · 斜面双光电门测动摩擦因数 —— 实现笔记

最终结果：**VERDICT: PASS**（第 1 轮即通过全部 13 条断言；第 2、3 轮是修视觉 bug 后的复跑，也全绿）

## 1. 四个倾角的完整数值表

常量（全部来自 spec）：`g = 9.8 m/s²`、`μ_true = 0.30`、`d = 5.25×10⁻³ m`、
`s_A = 0.25 m`、`L = 0.50 m`、`s_total(u=1) = 0.80 m`。

推导链：

```
a  = g(sinθ − μcosθ)                     牛二，与质量无关
vA = √(2a·s_A)      vB = √(2a·(s_A+L))   由静止 v² = 2as
ΔtA = d/vA          ΔtB = d/vB           遮光片极窄，平均速度代瞬时速度
μ_calc = tanθ − (vB² − vA²)/(2gL·cosθ)
       = tanθ − 2aL/(2gL·cosθ) = tanθ − (sinθ − μcosθ)/cosθ = μ   ← 解析上恒等，与 θ 无关
```

| case | θ/° | a /(m·s⁻²) | v_A /(m·s⁻¹) | v_B /(m·s⁻¹) | Δt_A /ms | Δt_B /ms | μ 反算 | Δt_A·v_A /m | Δt_B·v_B /m | 真实过程时长 T/s |
|------|-----|-----------|--------------|--------------|----------|----------|--------|-------------|-------------|------------------|
| th20 | 20  | 0.58910   | 0.54273      | 0.94003      | 9.6734   | 5.5849   | 0.300000 | 0.00525000 | 0.00525000 | 1.6480 |
| th30 | 30  | 2.35389   | 1.08487      | 1.87905      | 4.8393   | 2.7940   | 0.300000 | 0.00525000 | 0.00525000 | 0.8245 |
| th45 | 45  | 4.85075   | 1.55736      | 2.69743      | 3.3711   | 1.9463   | 0.300000 | 0.00525000 | 0.00525000 | 0.5743 |
| th60 | 60  | 7.01705   | 1.87311      | 3.24431      | 2.8028   | 1.6182   | 0.300000 | 0.00525000 | 0.00525000 | 0.4775 |

（`check.py` 打的就是这张表，四个倾角 μ 反算值与 0.30 的偏差都在 1e-16 量级，
远小于容差 0.004；Δt·v 与 d 的偏差是 0，远小于 2e-5。）

几个顺手记下来的量：

* 临界倾角 `arctan(μ) = 16.6992°`。θ 小于它 a ≤ 0，`√(2as)` 直接 NaN。
  所以倾角滑块的 `min` 取 20（a = 0.5891 > 0），并且 `model()` 里另加了 `a ≤ 1e-6 → a = 1e-6` 的防守，
  保证任何输入都不可能把 NaN 灌进 SVG（L3 会逐个词扫 `NaN/Infinity/undefined/null`）。
* `u → s` 的映射取「过程时间线性」：`t = u·T`，`s = ½at² = s_total·u²`。
  这样 `s(0) = 0`、`diff(s) ≥ 0`、`s(1) = 0.80 ≥ s_A + L = 0.75`，三条同时满足，
  而且和 `step()` 里的画法是同一份公式（step 只是把 T 统一慢放到 2.6 s）。
* 真实过程只有 0.48–1.65 s，60° 时不到半秒，直接实时播放什么都看不清。
  因此动画把每个倾角都等 u 慢放到 2.6 s（慢放 1.58×–5.44×）再定格 0.9 s 循环。
  这只是播放速率，`probe` 的 u 仍严格是物理进度，不含定格。

## 2. 逐轮记录

**第 1 轮 —— PASS（13/13）。**
写代码前先用 `check.py` 把四个倾角的 a/v_A/v_B/Δt/反算 μ 打了表，并把 spec 里 13 条
`invariants` 的表达式在 Python 里逐条复算了一遍（全 OK），确认物理没有歧义之后才动 JS，
所以门禁这一层没有反复。没有失败的断言 id。

**第 1 轮之后发现的渲染 bug（门禁查不出来，是我自己截图查出来的）：斜面整体不可见。**
断言只跑 `probe`，不看像素，所以这个 bug 完全不会让 verify 变红——但场景是废的。
症状：楔形填充、A/B 标签、角度弧都在，唯独 `<g id="q12-slope">` 里的斜面线、两个光电门、
滑块全部消失。用 `getScreenCTM()` 一量才明白：我把

```
transform="rotate(30, 296, 252)"
```

当成了「先把局部原点搬到 (296,252) 再转 30°」。实际 SVG 的 `rotate(a, cx, cy)` 是
**在同一套坐标里绕 (cx,cy) 旋转**，并不平移原点。我的局部坐标是 x∈[−240,0]（原点在斜面底端），
被绕 (296,252) 一转就飞到了 (−42,−234) 一带，整组元素跑到画布外。
改成 `transform="translate(296,252) rotate(30)"` 后正确——这也正是 JS 里 `rot()` 辅助函数
（`x' = 296 + lx·cosθ − ly·sinθ`）所对应的矩阵，两边这才自洽。

**第 2 轮 —— PASS（13/13）。** 除上面的 transform 修正外，顺带调了两处视觉：
滑块改画在光电门支架**之前**（支架是空心描边，这样滑块是「穿过」门而不是「盖住」门）；
「由静止释放」标签从 (XREL, −30) 挪到 (XREL−8, −38)，避免 60°/65° 时和滑块、遮光片叠在一起。

**第 3 轮 —— PASS（13/13）。** 清掉调试用的临时截图文件后的最终复跑，figure/js 的 sha 与第 2 轮一致。

失败断言 id 汇总：**三轮均为空**。

## 3. 哪一条断言最难满足

单看数值，13 条里没有一条是「难算」的——spec 把物理量给全了，`free_parameters` 确实是「无」。
真正需要小心的是这两条，它们考的都不是物理而是**实现纪律**：

1. **`th45-gateA-width` / `th45-gateB-width`**（`|Δt_ms × 1e-3 × v − d| ≤ 2e-5`）。
   这条是全场唯一一个把两种单位摆在同一个等式里的断言：probe 必须按 `units` 字段以**毫秒**报
   `dtA_ms`，而断言在**国际单位**下校验。内部我一律用秒算（`dtA = d/vA`），只在 `probe` 返回的
   最后一步乘 1000，绝不让 ms 进入任何中间计算。容差 2e-5 相对 d = 5.25e-3 只有 0.38%，
   等价于要求 Δt 精确到千分之四——只要在中间某处混了一次单位（比如把 `d` 当 5.25 mm 直接除以 v），
   结果会差 1000 倍，一定被逮住。

2. **`th30-s-monotone`**（`s[0] = 0` 且 `diff(s) ≥ 0` 且 `s[-1] ≥ 0.75`）。
   难点不在不等式，而在**读懂 u 的语义**：契约第 3 节写明 u 是物理进度、不含定格和回放停顿。
   我的 `step()` 是「跑 2.6 s + 定格 0.9 s」循环的，如果图省事把 `probe` 也按播放相位算，
   u ∈ [0.74, 1] 这一段会全部压在 s = 0.80 上——`diff(s) ≥ 0` 仍然成立，`s[-1]` 也够，
   居然照样能过，但 u 的物理含义就已经错了。这类「断言过了但语义错了」的坑比断言本身更值得警惕。
   我的做法是把 `probe` 和 `step` 彻底分层：`probe(u)` 只走 `s = s_total·u²` 这一条纯函数路径，
   `step(t)` 先把 t 折算成 u 再调同一份 `model()`，二者共用一套物理，谁也不污染谁。

另外，`th20-slides`（a > 0.05）本身平凡（a = 0.589），但它其实是在提醒
「μ = 0.30 时 θ 必须大于 16.7° 才滑得动」——这个提醒直接决定了倾角滑块的取值下限，
是全 spec 里性价比最高的一条断言。

## 4. spec 写得不清楚、让我走弯路的地方（如实写）

按对我实际造成的代价排序：

1. **`process_endpoints` 里 `s ≥ s_A + L` 是不等式，但没说 u=1 到底停在哪。**
   「u = 1 对应滑块已通过 B 门并到达行程终点（s ≥ s_A + L）」——「行程终点」是个未定义的量。
   取 0.75（正好到 B 门）还是取 0.80（越过 B 门一段）都满足断言，可这两种取法画出来的动画
   差别很大：取 0.75 的话滑块最后停在 B 门正中间，遮光片卡在光路里，看着像坏了。
   我自己定了 0.80（B 门后再留 0.05 m 缓冲），但这是**猜的**。
   建议 spec 直接给 `s_end` 常量，或者干脆把 u=1 定义为「遮光片后沿离开 B 门的瞬间」。

2. **`sample_points: 401` 与断言几乎全用 `[-1]` 之间是矛盾的。**
   13 条断言里有 12 条只看序列最后一个采样点，只有 `th30-s-monotone` 真的用到了整条序列。
   也就是说 401 个采样点里有 400 个基本没被检验。第一遍读 spec 我以为
   「a、vA、dtA_ms 会在每个 u 上被逐点检验」，为此认真想过「过 A 门之前 vA 该不该报值」
   （物理上还没测到，报 0？报 NaN？）——最后发现 `probe_key_meaning` 里已经写了「常量」，
   全程报同一个值即可。这个信息藏在 `probe_key_meaning` 而不是 `probe_keys` 旁边，
   建议把「常量 / 随 u 变化」这个二分提到更显眼的位置，或者干脆加一条断言把它钉死
   （例如 `std(a) == 0`），否则「常量」只是注释、没有约束力。

3. **`scene_requirements` 是自然语言，而门禁一条都不查。**
   「斜面随所选倾角真实旋转」「每跑完一个倾角就打一个点」「实时读数」这四条，
   verify.py 里没有任何对应检查（L1 只查静态文本、L3/L4 只碰 probe）。
   我那个把整个斜面转飞出画布的 transform bug，**三层门禁全绿**，
   是我自己截图才发现的。这是当前 harness 最大的盲区：
   `probe` 全对 ≠ 场景能看。建议至少加两条廉价的静态/运行时检查：
   (a) 渲染后取 `svg.getBBox()` 或若干关键元素的 `getBoundingClientRect()`，
   要求落在 viewBox 内、且面积非零；
   (b) 对声明了「随参数旋转」的场景，抽两个不同参数值跑 `step()`，
   要求目标元素的 `getScreenCTM()` 确实不同。

4. **`units` 字段是一句散文，不是结构化的。**
   「长度 m，时间 s，加速度 m/s²，遮光时间以毫秒(ms)报出」——毫秒这个例外藏在句尾，
   而 `probe_keys` 里 `dtA_ms` 的 `_ms` 后缀是唯一的第二次提示。
   建议做成 `{"dtA_ms": "ms", "s": "m", ...}` 的逐键单位表，让实现方无从误读。
   （这次没出错，纯粹因为提示语专门点了这一条。）

5. 小问题：`stem` 里说 d「由游标卡尺测得」，`constants` 里给的是 `D_WIDTH: 0.00525`。
   5.25 mm 恰好是「游标卡尺 20 分度、0.05 mm 精度」的读数，这个细节其实很值得在图上讲
   （题目考的就是读数），但 spec 没有把它列进 `scene_requirements`，也没有 `disclosures` 要求。
   我只在 figcaption 里提了一句「（游标卡尺读数）」。如果这是产品要教的知识点，应当显式要求。

## 5. 文件说明

| 文件 | 作用 |
|------|------|
| `q12.figure.html` | 单个 `<figure data-scene="q12">`，viewBox `0 0 560 320`。左：可转斜面 + 两个光电门 + 滑块；右上：μ−θ 图；右下 + 左下：实时读数与公式；`.ctl` 里是倾角 range 滑块。 |
