# q14 · 质谱仪中两种氖离子的分离 —— 实现笔记

## 1. 物理数值表

全部由 `check.py` 独立算出（不含任何拟合/试凑，均为闭式解）。

| 量 | 符号 | 数值 |
|---|---|---|
| 磁感应强度 | B | 0.1 T |
| 入射速率 | v | 9.6×10⁴ m/s |
| 离子①（打在 M）比荷 | (q/m)₁ | 4.800000×10⁶ C/kg |
| 离子②（打在 N）比荷 | (q/m)₂ | 4.363636×10⁶ C/kg = (q/m)₁ / 1.1 |
| 离子①半径 | r₁ = v/[(q/m)₁B] | 0.200000 m（OM = 2r₁ = 0.400 m） |
| 离子②半径 | r₂ = 1.1 r₁ | 0.220000 m（ON = 2r₂ = 0.440 m） |
| 回旋角速度① | ω₁ = (q/m)₁B | 4.800000×10⁵ rad/s |
| 回旋角速度② | ω₂ = (q/m)₂B | 4.363636×10⁵ rad/s |
| 半圆用时① | t₁ = π/ω₁ | 6.544985×10⁻⁶ s = **6.5450 μs** |
| 半圆用时② | t₂ = π/ω₂ | 7.199483×10⁻⁶ s = **7.1995 μs** |
| 时间比 | t₂/t₁ | 1.100000 |

推导链：
1. 垂直边界入射 ⟹ 洛伦兹力 qv×B 沿边界方向 ⟹ **圆心落在 PP′ 上** ⟹ 走恰好半圆，落点到 O 的距离 = 直径 2r。
2. ON = 1.1 OM ⟹ 2r₂ = 1.1·2r₁ ⟹ r₂ = 1.1 r₁ = 0.22 m。
3. r = v/[(q/m)B] ⟹ (q/m)₂ = v/(r₂B) = (q/m)₁/1.1 ≈ 4.36×10⁶ C/kg。
4. t_half = π/[(q/m)B] 与速率无关 ⟹ 比荷小 1.1 倍 ⟹ 周期长 1.1 倍 ⟹ **②（打在 N 的）后到达边界**。

**方向性结论（本题最易答反处）**：比荷小 ⟹ 半径大 ⟹ 周期长 ⟹ 后到达。
实现里我把「① = 比荷大 = 半径小 = 打在 M = 先到」这条对应关系写进了变量名
（`QM1/R1/arc1/M` 全部同族），避免中途串号。

## 2. 归一化时间轴的定义

按 spec 的 `process_endpoints`：**u = 1 是较慢的 ② 号刚好到达边界**，所以

```
t(u) = u · t₂            (t₂ = 7.1995 μs，慢者的半周期)
θ₁(u) = min(ω₁·t(u), π) = min(198°·u, 180°)
θ₂(u) = min(ω₂·t(u), π) = 180°·u
```

① 号在 u = 1/1.1 ≈ 0.9091 就到 180°，此后 `min` 钳位保持 180°，既不再增长也不回绕。
`t_us = t(u)·1e6`，而 `time-consistent` 是在秒下比对 `π/[(q/m)₂B]`，
所以 probe 里的量纲换算只在最后一步做一次：`t_us: c.t * 1e6`，`c.t` 全程是秒。

## 3. 逐轮记录

| 轮次 | 结果 | 说明 |
|---|---|---|
| 1 | **PASS**（11/11 断言） | 首轮即全绿 |
| 2 | **PASS**（11/11 断言） | 纯视觉微调，无断言相关改动 |

**没有任何一轮出现断言失败**，原因是先做了两项 pre-flight：

- `check.py` 用 Python 按同一套公式重建了 401 点采样序列，并**直接 eval 了 spec 里
  的 11 条 invariants**（复用 verify.py 的 helper 命名空间）。写 JS 之前就确认
  `omega-ratio` 取 `th*[100]`（即 u = 0.25）时两者都还在飞（49.5° / 45.0°）、
  `M-lands-first` 取 `th*[380]`（u = 0.95）时 ①=180.0 / ②=171.0 都落在容差内。
- `check.py` 里还内置了一份 **verify.py 同款字宽估算**（CJK 11.5 / ASCII 6.6，上限 552）
  的文本溢出自检。它抓到了一处会直接触发 `L1/overflow` 的问题：
  抬头第一行 `匀强磁场 B = 0.1 T 垂直纸面向外；两种氖离子以相同速率 v = 9.6×10⁴ m/s 垂直 PP′ 同时从 O 射入`
  估宽右端 = **575.6 > 552**。删去「匀强」「种氖」四字后降到 529.6。
  这处如果不预检，第 1 轮就会挂 L1。

第 2 轮改的两件事（都不影响物理）：
- `v₁` / `v₂` 两个标签在出发瞬间几乎重叠（两离子同一点出发、方向相同），
  给 `one()` 加了 `ldx/ldy` 偏移参数，①标签放箭头右侧、②标签放左侧。
- 「圆心」文字 x 从 240 移到 258，正对两个圆心点（262 / 277）。

## 4. 最难满足的断言

`time-consistent`：`abs(t_us[-1]*1e-6 - pi/(qm2[-1]*B)) <= 2e-8`。

难点不在数值精度（我让 `t_us` 直接由 `TH2 = π/(QM2·B)` 乘 1e6 得到，误差 ~1e-22），
而在于它同时锁死了三件事：

1. **u=1 必须对应慢离子**。若按「快离子落地」定义 u=1，t_us[-1] 会是 6.545 μs，
   与 π/(qm2·B)=7.199 μs 差 6.5e-7，超容差 32 倍 —— 而且此时 `half-circle-2`
   会读出 163.6° 一起挂掉。
2. **μs / s 换算不能漏**。忘乘 1e6 的话差值是 7.2e-6，超容差 360 倍。
3. **qm2 必须是"小的那个"**。若把 qm1/qm2 写反，这条会指向 6.545 μs，
   连带 `qm2-smaller`、`M-lands-first` 一起翻车。

也就是说这一条是三处「方向/定义」错误的联合探测器，是整套断言里信息量最大的。
相比之下 `angles-monotone` 只要用 `min(x, π)` 钳位就天然满足。

## 5. spec 里我认为写得不够清楚的地方（供产品改进）

1. **`probe_keys` 里的 `u` 到底该返回原样还是钳位值没说死。**
   `probe_key_meaning` 写「等于传入的 u」，但 L3 只在 [0,1] 上采样，两种写法都能过。
   如果将来加一条 `u[-1] == 1` 之类的断言，这里就会出现歧义。建议明确
   「probe 收到越界 u 时的行为」（钳位 / 未定义 / 允许外推）。

2. **`th1_deg[100]` / `th1_deg[380]` 这种硬编码下标与 `sample_points` 强耦合。**
   断言里写的是下标，`why` 里写的是 u=0.25 / u=0.95，两者只有在 `sample_points=401`
   时才等价。实现者必须自己反推 `i/(N-1)` 这个映射（我是从 verify.py 源码里
   `u = i / (N - 1)` 确认的，而 CONTRACT.md 并没有规定采样点是闭区间等距）。
   建议 spec 直接写成 `interp(0.25, u, th1_deg)`，或者在 CONTRACT.md 里
   把「u_i = i/(N-1)」写成契约的一部分。

3. **`process_endpoints` 说了 u=1 的物理含义，但没说到达边界后「保持 180°」是硬性要求。**
   这条实际藏在 `angles-monotone` 的 `why` 里（"停在 180 而不是回绕"）和
   `probe_key_meaning` 里（"到达边界后保持 180"）。三处分散描述同一件事，
   而任务提示词里反而讲得最清楚。建议把「越过终点后的钳位约定」提升为
   `process_endpoints` 的一部分。

4. **`scene_requirements` 要求「标注慢放倍数」，但没给量纲基准。**
   真实过程 7.2 μs、动画播放几秒，慢放倍数是实现者自选的（我取 5×10⁵，
   对应弧段 3.5997 s）。这个自由参数没有出现在 `free_parameters`（那里写的是"无"），
   严格说是不一致的 —— 渲染时间轴确实是自由的，只是不参与断言。

5. **`units` 说"角度以度(°)报出"，但 `constants` 里给的 `V/B/QM1` 是 SI，
   而断言 `time-consistent` 又在秒下比对 `t_us`。** 单位在 probe 层是混合制
   （长度 m、比荷 C/kg、角度 °、时间 μs），断言层却要换回 SI。
   这个"报出单位 ≠ 断言单位"的设计是本题唯一真正的坑，建议在 `units` 字段里
   显式写一句「断言在 SI 下检验，probe 返回值需按 probe_key_meaning 的单位报出」。

6. 小瑕疵：`stem` 里写 `v = 9.6×10⁴ m/s`，`constants` 里是 `"V": 96000.0`，
   一致；但 `physics.given_facts` 的 F1 写 `r₁ = 0.20 m` 只给两位有效数字，
   而断言容差是 `1e-4`。按 F1 的字面精度（0.20）刚好卡在容差边缘（0.20 vs 0.2 相等，
   侥幸通过），如果换成 `r₂ ≈ 0.22` 配 `5e-4` 也一样。建议 given_facts 给足位数，
   避免实现者照抄字面值。
