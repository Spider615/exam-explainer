# exam-explainer

把电子试卷转成「逐题讲解 + 物理驱动的矢量动画」的生成管线。

本目录目前是**验证性骨架**，不是完整产品。它要回答的问题只有一个：

> 把「正确性」从概率变成红绿灯，可行吗？成本是多少？

## 核心架构判断

生成和验证不是两个阶段，是一个循环。所以引擎必须能**执行代码**——
解物理参数要跑 Python，验证渲染要跑无头浏览器。纯文本生成做不到这件事，
而可视化恰恰是最擅长掩盖错误的形式：一段由牛顿方程积分驱动的动画讲错了，读者会信。

因此本项目把职责切成两半，中间是一条不可逾越的红线：

```
      题目结构化记录（spec）              ← 人 / 独立模型产出，沙箱只读不可改
      ├── stem            题干
      ├── physics         权威解法：力的形式、方程、题目给定事实
      ├── cases           要覆盖的情形
      ├── probe_keys      场景必须暴露的物理量
      ├── invariants      渲染后必须通过的物理断言   ← 治「参数不自洽」
      └── disclosures     放大/归一化的必填披露      ← 治「作图参数被当物理量」
                    │
                    ▼
      沙箱 agent（可写代码、可跑 Python、可跑无头浏览器）
      循环：解参数 → 写场景 → verify → 失败就重来
                    │
                    ▼
      绿灯出货  /  红灯进人工队列
```

**写代码的那一方不能写断言。** 自己给自己出卷子的验证等于没验证。

## 门禁能保证什么、不能保证什么

| | |
|---|---|
| ✅ 能 | 代码不崩、引用的 id 都存在、渲染无 NaN、probe 是纯函数、数值满足物理断言、参数自洽有解 |
| ❌ 不能 | **这道题的解法对不对**、这个可视化选得好不好、**断言本身写得对不对** |

绿灯 ≠ 正确。绿灯 = 实现与 spec 一致。解法正确性仍然要人审——
但人审的对象从「7 KB 物理仿真代码」变成了「一段解法文字 + 一组断言」，便宜一个量级。

## 管线现状

全部接通，而且**上传一份 PDF 会自动跑完 ① → ⑦**：

| | 环节 | 实现 | 用什么模型 |
|---|---|---|---|
| ① | PDF 摄入 | `pipeline/ingest.py` | 否 |
| ② | 题目切分 | `pipeline/segment.py` | 否 |
| ②b | 公式识别 | `pipeline/mathvlm.py` | 视觉模型（按图哈希缓存） |
| ③ | 解题 | `pipeline/solve.py` | **DeepSeek → 视觉模型**（两级） |
| ③b | 目录：短标题 / 短答案 | `pipeline/outline.py` | DeepSeek（整卷一次调用，③ 跑到一半也会滚动刷） |
| ④c | 动画选题 | `pipeline/pick.py` | DeepSeek（整卷一次调用） |
| ④ | 写 spec / 断言 | `pipeline/spec.py` | claude-sonnet-5（走本机订阅） |
| ④b | spec 自检 | `pipeline/speccheck.py` | **否 —— 是一次计算** |
| ⑤ | 生成场景 | `pipeline/scene.py` | claude CLI 沙箱 agent（走本机订阅，多题并行） |
| ⑥ | 验收门禁 | `harness/verify.py` | 否 |
| ⑦ | 装配成页 | `pipeline/assemble.py` | 否 |
| ⑧ | Web / 上传 | `pipeline/api.py` + `web/` | 邮箱验证码登录，试卷按账号隔离 |

> **表按执行顺序排，不是按编号排。** ④c 跑在 ④ 前面 —— 编号是先有的，
> 顺序是后来按成本改的，见下一节。

### ⑤ 前面有三道闸门，从最便宜的开始

⑤ 一题几分钟到几十分钟。所以在花这个钱之前要先答三个问题，**顺序按单价排，不按编号排**：

```
④c 做了有没有增量？     动画能不能说出静态图说不出的东西       一次调用，28 秒/整卷
④  这道题做不做得了？   写不出数值断言就 animatable=false     两次调用，约 6 分钟/题
④b spec 自不自洽？      拿它自己的参考实现验它自己的断言       纯计算，9 秒/卷
```

**便宜的筛子必须排在贵的前面**，这条是踩出来的：④c 原来排在 ④ 之后，于是 ④ 会给整卷每一道题都写一份完整 spec，然后 ④c 再把其中大半刷掉 —— 那些 spec 从写出来的那一刻起就没人会用。

库里还留着旧顺序的两卷：**重庆卷** 15 题写满 15 份 spec，最后出了 5 个动画；**海南卷** 写了 13 份（其中 9 份 `animatable`），动画一个没出。按一道 6 分钟算，这是每卷半小时以上的纯浪费 —— 而且浪费的是 ④ 那一步，正好是整条链上最贵的一步。

换成新顺序之后的**福建卷** 16 题：④c 一次调用判完整卷、挑出 6 道 → ④ 只给这 6 道写 spec → ④b 通过 3 道 → ⑤ 绿灯 3 道。④ 的工作量从 16 道降到 6 道，**而被砍掉的那 10 道本来就一道都进不了 ⑤** —— 省掉的全是注定不会被用到的输出。

每一道被刷掉的题都留下一句人话理由（`anim_why` / `why_not`），页面上答得出「这道题为什么没有动画」，而且分得清「做不了」和「没必要」。

④b 和 ④c 是两件事，不能合并：前者查的是「spec 有没有自相矛盾」（`a = Fc + Fs − 1` 配上正确的终点值，两者不可能同时成立），后者查的是「值不值得」（两个力求合力做得了，但一段动画对它没有任何增量）。④ 的 `animatable` 和 ④c 的 `worth` 同理 —— 一个答「做不做得了」，一个答「做了有没有增量」。

原来 ⑤ 的入口是人审 `specs.status`。要做到全自动，就得拿一个**不是人**的东西顶上，
而不是 `--allow-draft` 把它跳过去 —— ④b 顶的就是这个位置。但它只查 spec 内部矛盾：
③ 从一开始就理解错题、④ 忠实地写成彼此自洽的错 spec，这一关照样全绿。
那要对照原卷，是人的活。所以页面上写的是「自检自洽」，不是「已通过审核」。

**三个环节三个模型三个进程**，不是为了炫技 —— 是「写代码的那一方不能写断言」这条
红线要靠进程边界保证，不能靠提示词里的一句嘱咐。

### ③ 解题：两级链路

DeepSeek 没有视觉通道（实测 `image_url` 直接 400），而 82% 的题带插图。
但**「带插图」不等于「必须看图」**：实测重庆卷 13 题，DeepSeek 独立答对 8 道，
另外 5 道老老实实回 `NEED_FIGURE` 而不是编一个读起来合理的答案 —— 一次都没瞎猜。

```
DeepSeek 盲试 ──能解──→ 采用（免费通道，实测覆盖六成）
             └看不到图→ 豆包 doubao-seed-2-0-pro（图直接进 payload，一次调用）
```

不走「图→文字→解题」：那会把一个看得见的错换成看不见的错。
描述里把 37° 写成 53°，下游会一本正经算出一个毫无破绽的错答案。

> **单次调用的答案不可信。** 实测同一模型对福建卷第16题先后给出 `√7·v₁` 与
> `(1+√3)v₁`（后者经门禁的数值仿真证实为对），**两次都自称 `high`**。
> 所以有 `--crosscheck`：独立解两遍，不一致就强制降为 `low` 并把分歧写进页面。
> 压轴题上模型的自评置信度没有区分力，只有独立复核能暴露这件事。

产出不只是答案。`figure_reading` 单列「从图里读到了什么」，`assumptions` 单列
「题面没给、自己补的前提」—— 读图错了推导会显得完全合理，单独列出来人对着原图
扫一眼就能发现，不必读完整段推导。实测豆包把 `270mV` 读成 `260mV`，这一栏当场暴露。

### ④ 写断言：整条链上唯一没有下游检查的环节

解法错了断言能抓，实现错了断言能抓，**断言自己错了没有任何东西能抓**。
而且它错得很隐蔽：写松了（`<= 100`）永远绿灯；物理量名写错（`vA` 写成 `v_A`）
L4 会报「case 没有采样数据」而不是失败 —— 这条断言等于没写。

所以 `spec.py` 自带 `lint()`，专抓「不会报错、只会让门禁失效」的写法，并强制三类覆盖：
终点值、单调/守恒、**物理量之间的自洽**（如「速度取极值处加速度必须为零」）。
最后一类最容易漏，但它抓的是 probe 内部自相矛盾 —— 实现方可能让 `v` 与 `a`
各算各的，数值上互不相干却都满足各自的终点值。

产物一律先落 `status='draft'`，过了 ④b 自检才转 `approved`、才进得了 ⑤ ——
那个位置早先站的是人审，现在站的是一次计算（见上一节）。`animatable=false`
是诚实阀门：静态题写不出数值断言，与其编几条永远成立的假断言，不如明说它
不适合做成动画（实测重庆卷 15 份 spec 里 4 道如此）。

`lint()` 抓到的问题**不拦**这份 spec，只记进 `why_not` 一起落库（跑 ④ 时也会
逐条打在日志里）。真正的闸门是 ④b —— **形式检查查不出力的方向写反了**。

### ⑤ 生成场景：唯一带反馈的环节

```
spec ──→ 沙箱 agent（解参数 / 写 SVG+JS / 跑门禁 / 读报错 / 重来）──→ 绿灯
```

红线不是靠嘱咐：spec 与 `harness/` 的 sha256 在**每轮结束后重新校验**，动过这一轮作废。
而且不采信 agent 自称的 PASS —— 它可能没跑、跑错目录、看错末行，`passed` 一律由
`verify.py` 的末行决定。

> 阶段④ 给的 id 形如 `q16`，会和 `specs/` 下受保护的人工版同名。
> 直接落盘就是覆盖只读文件，而且是在篡改检查抓住之前先毁掉原件 ——
> 所以写盘前先避让，同名一律加 `-genN` 后缀。

一条命令：

```bash
.venv/bin/python pipeline/run.py <试卷.pdf> -o work/<name>
```

自动链是 **① → ② → ②b → ②c → ③ → ③b → ④c → ④ → ④b → ⑦ → ⑤ → ⑦**，
命令行与网页上传**跑的是同一串**。两条入口必须一样长：不然「上传的卷子」和
「命令行跑的卷子」会在页面上呈现出两种完成度，而没有任何东西会提示这件事 ——
网页那条链一度只跑到 ③，页面上的「⑦ 呈现」却硬编码成绿的。

**⑦ 装两次，不是笔误。** ⑤ 可能要跑一两个钟头，而 `out.html` 是这条链唯一的
离线交付物 —— 让它一直缺着，等于这段时间里「导出的那份」根本不存在。
所以先装一版无动画的，⑤ 跑完再装一版带动画的。网页那条路不受影响：它读库，
⑤ 每绿灯一道题，刷新一下就多一个动画。

**⑤ 现在在链里**，早先不在 —— 那时它的入口卡着人审 `specs.status`，自动往下跑
等于让模型自己写的断言直接进动画。顶替人审的是 ④b：拿 spec 自带的参考实现跑一遍，
满足不了它自己的断言就 rejected，进不了 ⑤。**是一次计算，不是再问一个模型**。

切分完（3 秒）就放人进去看，解题在后台逐题填 —— 一道两三分钟，
让人干等半小时才看到题目是不可接受的。③b 目录也不等 ③ 全解完：
每解完几题就滚动刷一次，所以「答案速览」是边解边长出来的，
而不是最后一道题解完才整片出现。
③④⑤ 任何一步没跑成都不算整条任务失败（页面照实标「无断言 · 未被检验」、
没动画的退回原卷插图），⑦ 失败才是失败。

### ① 摄入踩到的两个坑（都会随卷子种类放大）

- **文字层混入康熙部首**。`⾼`(U+2F98) 不是 `高`(U+9AD8)，肉眼无差别，
  但 `"高考"` 直接搜匹配 0 次。本卷 537 处、46 种。做**选择性**规范化：
  折叠兼容字形，但**保留全角标点**（NFKC 会把全角逗号压成半角，破坏正文排版）。
- **文本位置要 `tm` 乘 `cm` 才对**。直接取 `tm[4]/tm[5]` 得到的是排版局部坐标。
  更麻烦的是题型标记那一行的 `tm` 是退化单位阵，自身无有效坐标，
  必须回退到相邻文本块——所以 span 要带 `ok` 标志。

### ②b 公式为什么必须交给视觉模型

从 PDF 矢量数据反推公式的二维结构，本质是**PDF 数学公式识别**——
有专门研究领域的难题。纯几何规则（`mathfix.py`）做到约 85% 就到顶，
剩下的都是**几何上无法区分**的歧义：上下堆叠的两个选项，
A 的分母和 C 的根号上横线只差 9pt，任何基于距离的判据都会串味。

真正决定架构的是**失败模式的不对称**：

| | |
|---|---|
| 裁图裁歪了 | 一眼看得出 |
| 结构解析错了 | `√rg` 和 `√(r/g)` 长得都像对的，**看不出来** |

对给学生看的产品，后者不可接受。所以：

> **裁得宽松一点，让模型同时做版面分析和公式识别。**

精确裁出每个公式又会掉回版面分析的坑；裁整个**选项块**，让模型输出
`{key, latex}` 数组反而更稳——实测 2×2 列主序布局（左列 A、B，右列 C、D）
几何解析四个选项全错，模型一次全对。

流程：用已有的逐字符坐标框出选项区 → 300dpi 渲染裁图 → 降到 150dpi →
**按图片内容哈希查缓存** → 未命中才调模型 → LaTeX 写回 questions.json。
页面用 KaTeX 渲染，同时保留原卷截图作为兜底与「对照原卷」的依据——
**模型也会错，但错了必须能被看见**。

坑：框选项区必须限定在**本题的纵向范围**内（切分阶段存 `y_bounds`），
否则同一页上的几道题会互相串——实测第 1、2、3 题拿到了同一份选项。

### ② 切分的三条规则与三个坑

规则：题型标记（`单选题 (4分)`）作锚点而非阿拉伯题号；页眉页脚按「同位置同尺寸重复出现」剔除；
图文归属靠 (页, y) 落在相邻锚点之间。

坑：
- **选项之间没有任何分隔符**（`…697米B. 从O处…`），正则不能要求前导空白；
  改判「A/B/C/D 四个匹配连续且顺序正确」，`A点`/`图A` 就不会误伤。
- **大题标题必须是硬边界**，否则本大题末题的选项 D 会把
  「二、多项选择题（本题共4小题…」整段吞进去。
- **公式在文字层里会被拍平且不可恢复**。本卷第 8 题
  `ω=√[G(M+m)/(2R³)]` 变成 `ω=[G(M+m)2R3 ]12`。这类题必须退回页面图像，
  所以每题带一个 `text_quality`（ok / suspect / degraded）。
  注意要把它和「选项本来就是图片」（第 4 题）区分开——后者不是缺陷。

### ② 表格：二维的东西塞不进一维的题干

表内文字整体摘走，只在原位留 `〔表N〕`，内容另交视觉模型转写成 `rows`
（不摘的下场：`ΔWh/E_f/(/10((1010^(−2)_(−2)^(−3)mJJ))) 0.984.002.94`）。

**跨页表要认出来并合成一张。** 江苏卷第11题、江西卷第11题都是一张表被页面切断：
上半张贴在前页底部，下半张贴在次页顶部。分开渲染时下半张没有表头——
`0.120 0.140 0.160` 一行数字孤零零摆着，读者无从判断这是什么量。

判据只用版面事实，不看内容：相邻两页、左右边界对齐、上半张下方没有正文、
下半张上方没有正文。页码残留（`5 / 10` 拆出来的 ` /`）不算正文。

> 合并**只在读取时做**（`segment.merged_tables`），不回写 `questions.json`。
> 每张表的 `rows` 永远只是它自己那张裁图的转写结果——否则重跑一次 mathvlm，
> 上半张会被它自己的裁图覆盖回两行，而下半张的数据已经在上次合并时被删掉了，
> **无声地少一行数据**。列数对不上就不合并，宁可留两张各自完整的表。
> 「对照原卷」要把两张原图都给出，否则读者没法核对下半张是不是抄错了。

## Web 应用

```bash
brew services start postgresql@17 minio     # 依赖：库 + 对象存储
.venv/bin/python pipeline/store.py init     # 建表、建桶（幂等）
./run.sh                 # http://127.0.0.1:8712  （前端已构建时直接起）
cd web && npm run dev    # 前端热更新，5173，API 走 vite proxy 转 8712

.venv/bin/python pipeline/store.py stat     # 库里有什么
.venv/bin/python audit.py [卷名前缀…]        # 逐题体检
```

连接串与凭证全在 `.env`（已 gitignore，**不进前端**）：`DATABASE_URL`、
`EXAM_ASSET_STORAGE`、`MINIO_*`。

**分层**——管线必须是 Python（PDF 解析、坐标运算、数值求解、无头浏览器编排，
Node 生态没有对等库）；前端是 React + TypeScript + Vite；
后端 FastAPI **只做编排和数据，不拼 HTML**。

```
React + TS + Vite     上传 / 试卷库 / 逐题阅读 / 动画播放
      ↕ JSON API
FastAPI               POST   /api/upload · GET /api/jobs/{id}
                      GET    /api/papers · /api/papers/{name}
                      DELETE /api/papers/{name} · POST /api/papers/delete
                      GET    /api/papers/{name}/scene.js · /img/{fn} · /page/{n}
      ↕
store.py              Postgres（元数据） + MinIO（资产）
      ↕
ingest / segment      纯代码，无模型调用 → work/<卷名>/ → publish
```

### 存储：库是唯一真相源，工作目录只是构建产物

在这之前是「拿文件系统当数据库」，踩到两个真问题：

- **两棵树静默漂移**。`work/` 和 `work/_batch/` 曾是同一批卷子的两份副本。
  改完管线只重跑一棵，体检全绿，但页面上读的还是旧数据，没有任何机制能发现。
- **并发写竞争**。两个进程同时写一份 `questions.json`——`json.dump` 不是原子的。

所以 `work/<卷名>/` 降级成**构建产物目录**，`store.publish` 之后库才算数，
API 和 `audit.py` 都只读库。没 publish 就不存在，漂移无从发生。

| 存哪 | 什么 | 为什么 |
|---|---|---|
| 库·列 | `stem` / `options` / `tables` … | 前端要渲染、要查 |
| 库·`layout jsonb` | `y_bounds` / `y_range` / `box` / `fig_marks` | 只有 `mathvlm.py` 读回去裁图，拆成列没人会查 |
| MinIO | `img/` `page/` `mathimg/` + 源 PDF | 用户看得到的 |
| 哪都不去 | `_hires/`（300dpi 临时页渲染）`_cache/` | 裁完就没用，几秒能重算，不该占对象存储 |

两处刻意的设计：

> **`vlm_cache` 不挂 `paper_id` 外键。** 它按图片内容哈希存，跟卷子无关。
> 挂了外键就会随删卷级联清空——那等于每删一卷就把下次全量重跑的成本
> 从 20 次模型调用推回 300 次。没有可级联的路径，就不会被误删。

> **资产一律由 API 代理，不把对象存储地址给出去。** 代价是一次转发，换来
> 存储后端对前端完全透明：`EXAM_ASSET_STORAGE` 从 `local` 切到 `minio`，
> 前端 URL 一个都不用改。

删卷是一条 `DELETE FROM papers` 加级联，再清对象。对象 key 按内容哈希，
两卷共用同一张图时 key 相同，所以**只删没有其他卷再引用的**（SQL 里一个
`NOT EXISTS`），而且必须在库事务提交**之后**删——反过来一旦回滚，
库里就留下指向不存在对象的记录。

> 整页图的文件名不能猜：`pdftoppm` 按**总页数**决定补零位数，9 页的卷子是
> `p-1.png`，10 页以上才是 `p-01.png`。端点里曾写死 `p-%02d.png`，
> 结果所有 9 页以内的卷子整页图全部 404——而这条路径正是「对照原卷」的依据。

> 动画的帧循环在前端 `SceneMount.tsx` 里重写了一遍，没有复用
> `harness/_runtime.js`——那份挂在 `DOMContentLoaded` 上，SPA 里 figure 是
> 后渲染的，时机对不上。**场景契约本身没变**：场景只实现 `step(t)/reset()`，
> 谁来驱动由宿主决定。组件会把 api 挂到 figure 元素的 `__sceneApi` 上，
> 供无头探针主动驱动——虚拟时间下 rAF 几乎不推进，只靠截图判断「有没有动」必然误判。

## 契约要点

场景注册为 `window.Scenes["<id>"] = function(fig){ return {step, reset, probe} }`。

- `step(t)` —— 渲染。t 为秒、单调递增，帧循环由运行时负责，场景内禁用
  rAF/setTimeout/setInterval/SMIL。
- `probe(u, caseId)` —— **纯物理**。`u ∈ [0,1]` 是物理过程的归一化进度
  （不是屏幕播放时间，定格与回放停顿不计入）。返回 spec 声明的全部物理量。
  必须是纯函数：不碰 DOM、不改内部状态、同一入参恒返回同一结果。

`probe` 是整套架构的支点——它把「物理」从「像素」里剥出来，
断言才能写在物理量上，而不是写在渲染结果上。

## 五层门禁

| 层 | 查什么 |
|---|---|
| L1 静态 | 文件结构、`data-scene` 一致、viewBox 宽 560、无 `<script>/<style>`/外链/SMIL/硬编码颜色、id 前缀、**js 里 querySelector 的 id 是否真的存在于 figure**、必填披露、文本溢出 |
| L2 装载 | 无头 Chrome 加载，运行时必须成功注册并跑出首帧 |
| L3 探针 | 451 帧 `step()` 无异常、渲染后 SVG 无 NaN/Infinity/undefined、`probe` 纯净且返回有限数值 |
| L3.5 渲染覆盖 | **每个带 id 的 SVG 元素必须在某一采样时刻真的画在 viewBox 内**；画面必须随时间变化 |
| L4 断言 | 逐 case 采样 `probe`，用 spec 的 `invariants` 检验物理 |

### L3.5 是补出来的，值得单说

第一版只有四层。实测中一个场景把 `translate(cx,cy) rotate(θ)` 误写成
`rotate(θ cx cy)`，斜面线、滑块、两个光电门整组飞出画布——**画面上什么都没有，
四层门禁 13/13 全绿放行**。因为 `probe` 是纯物理函数，物理算得完全正确，
而没有任何一层去看渲染结果。

对一个卖可视化的产品，这个洞比解法的洞更致命：解法错了画面至少是像样的，
这个是画面直接没了。

L3.5 只查**位置**不查**可见性**：`opacity=0` 的元素 `getBBox()` 依然有效，
所以「结论框只在最后出现」这类合法隐藏不会被误伤；而「整组飞出画布」是全时段的，
必然被抓。零 spec 编写成本。

> 实现坑：算元素位置**不能用 `el.getCTM()`**——它含 viewBox 缩放，返回的是渲染
> 像素坐标（无头默认窗口 800px ÷ 560 用户单位 ≈ 1.425 倍），拿去和 viewBox 数值比
> 会把右下方元素全部误判出界。必须经 `svg.getScreenCTM().inverse()` 换回用户单位。

L1 的 id 引用检查针对的是历史最高频缺陷。注意它只认完整字面量
`querySelector('#xxx')`，`'#q16-' + n` 这类拼接不在静态检查范围内——
那类错误留给 L2/L3 抓。

## 运行

```bash
cd runs/q16
../../.venv/bin/python ../../harness/verify.py q16
```

末行输出 `VERDICT: PASS` 或 `VERDICT: FAIL`。失败时逐条列出层级、代码、原因，
L4 还会打印 `实测` 值。每次调用都会向工作目录的 `_verify_log.jsonl`
追加一条记录（轮次、verdict、失败断言 id、两个文件的哈希）——
**迭代轮次由门禁自己统计，不依赖被测方自觉**。

## 已知边界

- 只在**物理**一门学科上验证过。物理是目前唯一一门断言写得出来的学科
  （`v_A/v₁ == 2.00` 这种）。扩到数学（函数图像、几何）大概率成立，
  再往后要重新评估这套架构还成不成立，不能默认复用。
- 样本量极小。模板收敛性、动画的实际教学增量，都还没有数据。
- `verify.py` 的文本溢出检查是按字宽估算的粗查，不是真实排版测量。
